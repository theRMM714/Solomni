# Solomni

> **English:** [README_EN.md](README_EN.md) —— the same overview in English.

Solomni 是一个**跑在自己机器上的智能体运行环境（AgentOS）**：一个可执行程序 + 一个 `modules/` 文件夹
就是整个产品。没有安装程序、没有服务端、没有账号。

## 为什么需要它

**① 你有一个工具或工作流，想让 AI 用上它。**
常见的做法是把它包成某个产品专用的插件——包完就绑在那个产品上：换 agent、换平台要再包一遍，
那个工具本身也多了一层与主产品耦合的壳。这里需要**按契约适配一次**：一个文件夹 + 一份 `module.yaml`
（职责提示词 + 工具声明），命令还是它原本的命令；有些东西要动一点自己的边角（例如把可执行文件放进模块目录、
按契约约定参数的传法与回执的形状），但改动只落在它自己那边——不动代码结构、不引任何 SDK。
适配完之后**没有后遗症**：**契约之外双方互不依赖**——把平台拿掉，它照原样跑；把它从这个平台拿掉，平台也照常运行。
同一个能力，人走界面用、agent 走契约用，靠的是同一份声明，不必维护两套入口。

**② 多个 agent 一起干一件活。**
默认共享一个工作区的问题很具体：互相覆盖、产物归属不明、有人拿别人还没定稿的中间产物当事实继续做。
这里每个 agent 有**自己的沙箱**（`session/<工作名>/<agent 实例名>/`），它同时是共享区的**工作副本**；
共享区 `work/` 是**主副本、对 agent 只读**——要用的内容先 `work_pull` 拉进沙箱、改完 `work_commit` 提交回共享区。
提交按**文件级三方比较**判定，冲突整个拒绝并逐条点名，不会静默覆盖；任一提交点都能还原。
跨 agent 流动只有共享区与进入上下文的转录两条明路——谁的产物落在谁的格子里，返工找得到人；
能力也隔离，模块目录只归装了它的那个 agent。
（"谁只写哪一块"由**会话权限**落实：给每个 agent 配读写白名单 / 黑名单，提交只认白名单内的路径，模块目录默认只读；
见 [docs/permission/README.md](docs/permission/README.md)。）

**③ 出了事，你要知道它当时看到了什么、凭什么这么判。**
转录**只追加**（删除 / 恢复是显式动作，会真的重写流水）。任意一行点「回档到此处」：**留档**——追加一条标记、
把之前的行折叠起来（字节全留，随时可恢复）；**删除**——真的截断到那一刻；**恢复**——在标记处截断，
连同留档期间的新工作一起撤掉。行 id 单调、永不复用，回放可复现，**重建与实时逐条一致**；共享区也按提交记录上的
`(agent, 行)` 锚回到那一刻，整棵子树同步。一次交付能从盘上重放——AI 干过的活因此是能审计、能复现的工程制品，
而不是聊过就没了。

## 由什么组成

| 东西 | 是什么 |
| --- | --- |
| **核心** | 产品里唯一的程序（Rust）。提供机制：会话与转录、任务编排与验收、工具执行与围栏、登记处、回档与压缩 |
| **模块** | 一个文件夹 `modules/<id>/`：一份 `module.yaml`（职责提示词 + 工具声明）+ 工具本体。任何语言、任何能跑起来的东西 |
| **agent** | 名字 + 它具备的模块（可以为空：只用内建文件工具）+ 模型 + 自己的沙箱。模块被装进哪个 agent，就以那个 agent 的名义说话 |
| **使用者** | 人与 agent。人走界面（终端 / 本机网页），agent 走模块契约——同一批模块，两个门 |

## 当前能力

- **三种形态**（由用户在建工作时选）：
  - **单 agent**：一个 AI 装多份模块能力，直接干活；
  - **小组协作**：多个 agent 各持一份能力——建组 → 讨论 → 整理出任务链 → **审查关卡**（你点头才开工）→
    按阶段并发执行 → 每阶段一次验收 → 总验收 → 交付；没过只把点名的节点退回重做；
  - **代理**：把决定权整块交给核心，由它挑人、建子会话、代你回答关卡；目前从 API / 脚本进入。
- **模块即插即用**：`modules/` 里放一个带合法 `module.yaml` 的文件夹就出现，移走就消失——不注册、不编译、不重启。
- **会话与历史**：每个工作一个目录 `session/<工作名>/`；任意一行可「回档到此处」——**留档**（可再恢复）/ **删除**
  （真的截断）/**恢复**，共享区按行锚一起回到那一刻；转录可回放、上下文可压缩。子会话落在父会话的 `children/` 下
  （可再嵌套），整棵树共用**一个**共享区（版本化：`work_pull` / `work_commit`）。
- **三重隔离**：内置工具的越界拒绝 → 工具进程走守门进程（环境白名单 / 进程树 / 超时杀整棵树）→
  平台围栏（Windows AppContainer、Linux Landlock、macOS seatbelt）。装不上就如实报告能力等级，不假装有。
  围栏的授权落点分**必要**与**可选**：可选落点授不上只记事实；**必要落点授不上绝不静默降级**——
  弹一张卡让你选「本轮无围栏跑一次 / 放弃这次调用」，没有可回答的前端就拒绝执行（命令不落进程）。
- **登记处**：供应商 / 模型 / agent / 设置四份 YAML，全在 `.home/`，由界面管理。
  密钥只在本机登记处与核心的出站调用里（边界见 [REGISTRY_SPEC.md](REGISTRY_SPEC.md)）。
- **两种交互面**：终端转录中心（默认）与本地网页（`-webUI`，只绑 `127.0.0.1`，默认 3081）。
- **裁决只有一条通道**：任何要用户拍板的事——核心的各道关卡（名单 / 开工 / 方案待审 / 节点没过）、
  工具级确认、以及工具执行层自己发起的问题——都用同一张卡：**消息 + 选项**（选项 id 是契约，文案归界面），
  回答只有一条命令。它**必须阻塞**：不回答就不往下走；按停止 = 整队作废、等待方按"拒绝"解开。
  卡与回答随会话落盘，重启不重问已答的；构不出可用选项时**不弹卡**，而是停掉会话并落一条警告。

## 安装与运行

前置：**Node**（跑启动器）与 **Rust**（构建核心）。

```bash
node start.js            # 任意平台；Windows 也可双击 start.bat，macOS / Linux 也可 ./start.sh
node start.js -webUI     # 直接进本地网页（127.0.0.1:3081）
```

- 首次运行把工具链收敛在**项目内**（`platform/`、`.tools/`）：缺 Rust 会先征求同意再装，不动系统。
- **没有配供应商也能跑**：用内置假模型把流程演示一遍，并如实告知。
- 常用参数：`--root <目录>`（换产品根）、`--web-port <端口>`、`--release`。
- 终端提示符下的命令：`single <agent>…` / `collab <本次需求>` / `proxy` / `webui`。

### 配供应商与模型

在界面里加供应商（端点 + 密钥）与模型，并给核心选一个默认模型；密钥只写进 `.home/providers.yaml`，不回显。

## 模块契约

模块 = 一个文件夹 + 一份 `module.yaml`，**不依赖本项目的任何代码**；核心也不依赖模块的实现——
双方只依赖这份契约（完整字段与规则见 [MODULE_SPEC.md](MODULE_SPEC.md)）：

```yaml
id: research                 # 全局唯一，= 文件夹名
brief: 调研与对比选型。        # 能力简述：给核心选人看
system: 你负责调研……          # 职责提示词：管辖边界 + 本模块工具用法
runtimes: [python]           # 可选：工具需要哪些运行能力（版本由用户在会话里定）
tools:                       # 可选：外部工具表
  read_txt:
    command: python tools/read_txt.py   # 工作目录 = 本模块根目录
    params:
      path: { type: string, required: true, desc: 要读的真实绝对路径 }
```

- **调用约定只有一条**：一条启动命令 + 参数 + stdin/stdout 回执。脚本、skill、MCP、别的 harness 都是它的实例。
- 工具进程的可达范围 = 该 agent 的私有沙箱 + 它自己的模块目录；共享区主副本不在其中（要改先 `work_pull`，改完 `work_commit`）；只收**真实绝对路径**，越界即拒绝。
- **每个模块有一个恒可写的跨任务私有区** `<module>/userdata/`：载入模块时确保它存在（只建目录、幂等；
  建不了不阻断加载，只是如实标注那一席拿不到私有落点）；模块目录默认只读，`userdata/` 例外。
- 能跑通就是合法模块；跑不通时核心如实报错，不猜、不兜底。

### 跑一遍演示

演示是**真机测试**：走真实模型，会真的投喂资料、调工具、核产物。所以脚本开工前先核对条件——
前两个演示要三个模块在清单里、indexer 已构建、登记处有供应商与一个可用的模型（用 `SOLOMNI_DEMO_MODEL` 指定，或用核心默认）；
**代理演示**要登记处有供应商、模型与**核心默认模型**，清单里至少有一个模块或一个已存 agent。
**条件不齐就打印 `DEMO-SKIPPED` 与怎么补、以退出码 2 收场：不跑，也不用内置演示通道凑一遍。**

```bash
node start.js -webUI
node demo/run-demo.mjs         # 组合式：一个 agent 装三个模块（python / node / C++）
node demo/run-demo-collab.mjs  # 小组协作：三个 agent 各持一份能力协商，走完整条流程
node demo/run-demo-proxy.mjs   # 代理：只跟核心说话，它自己挑人、建子工作、被叫醒；停止即全停
```

C++ 模块要先编译一次（产物不入库），命令与理由见 [modules/indexer/README.md](modules/indexer/README.md)——前置检查会替你确认这一步。

## 还没接入

- **虚拟机档的 guest 本体**：选型、诊断、装配计划与逐项前置检测都已就位，guest 本体未接入，
  所以此刻**虚拟机档一律不可选**（界面会逐项列出缺什么、每项怎么补）。
- 工具通道的外部凭据托管（当前模块工具不得依赖任何凭据）、模块分发与市场、执行期并行调度的进一步放开。
- 所有未完成项、怎么补与验收标准只有一处权威：[tests/gaps.yaml](tests/gaps.yaml)。

## 它不是什么

- 不是模型或供应商：通道与密钥是产品资源，模型可以任意替换。
- 不是调度常驻进程的运行时：模块不常驻、不待命，只在被交付任务时工作一次。
- 不是常驻服务：只绑 `127.0.0.1`，没有服务端、没有账号。

**质量**：`node run-tests.js` 是唯一入口——T0（格式 / 编译 / clippy / 依赖重复 / 结构审查，零容忍）+ 单元 +
跨平台集成 + 前端冒烟 + 端到端；平台围栏的真机探针由三平台 CI 跑（见 [TESTING.md](TESTING.md)）。
