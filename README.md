# Solomni

> **English:** [README_EN.md](README_EN.md) —— the same overview in English.

Solomni 是一个跑在你自己机器上的**智能体操作系统（Agent OS）**。

## 一句话说清它是什么

**一个可执行程序 + 一个 `modules/` 文件夹，就是整个产品。** 没有安装程序、没有服务端、没有账号。

这个项目**不是给 agent 加工具，而是给工具或技能配一个 agent**：

- **模块 = 一个文件夹** = 一段职责提示词 + 可选的外部工具 + 一块私有工作区。
  放进 `modules/` 就出现，移走就消失——不用注册、不用编译、不用重启。
- **模块可以是任何东西**：一份提示词、一个 Python / Node / C++ 脚本、一个 skill、一个 MCP，
  甚至另一个 harness。它们都是**同一件事**——一条启动命令 + 一段职责提示词 + 一块私有工作区；
  模块只需要用 YAML 写一份 `module.yaml` 遵守契约，**不引入本项目的任何代码或依赖**。
  所以你的工具始终属于你：离开这个产品，它照样能跑。
- **说话的是 agent，不是模块**：一个 agent = 名字 + 它具备的模块 + 它的模型 + 它自己的沙箱；
  模块被装进哪个 agent，就以那个 agent 的名义说话。
- **形态随任务变**：同一批模块，可以装配成「一个 AI 装多份能力」（单 agent），
  也可以装配成「多个 AI 各持一份能力」（小组协作）；任务结束，装配解散，模块仍归各自。
- **本机自持**：本地网页只绑 `127.0.0.1`；密钥只在本机登记处与出站调用里，
  永不进入提示词、转录、日志或模块工作区。
- **转录即内容**：你看到的和进入模型上下文的是**同一份**；agent 的发言永远是数据，不是指令。

想读设计理念与不变量：[PHILOSOPHY.md](PHILOSOPHY.md)。

## 目前是什么状态

**已经能用**：

- **两种形态**：单 agent（直连式 / 组合式）与小组协作——建组 → 讨论 → 整理出一条任务链 →
  **审查关卡**（你点头才开工）→ 按阶段并发执行 → **每阶段一次验收** → 总验收 → 交付；
  验收没过时只把点名的节点退回重做（同阶段已通过的保持通过），流程由你用「停止 / 继续」控制。
- **两种交互面**：终端转录中心（默认）与本地网页（`-webUI`，只绑 `127.0.0.1`，默认 3081）。
- **会话与历史**：每个工作一个目录（`session/<工作名>/`），记录只追加、可回档到任意一行、上下文可压缩。
- **三层隔离**：内置工具层的越界拒绝 → 工具进程走守门进程（环境白名单 / 进程树 / 超时杀整棵树）→
  平台围栏（Windows AppContainer、Linux Landlock、macOS seatbelt）；装不上就如实报告能力等级，不假装有。
- **登记处**：供应商 / 模型 / agent / 设置四份 YAML，全在 `.home/`，由界面管理，密钥永不回显。

**还没接入（如实说，不夸大）**：

- **虚拟机档的 guest 本体**：选型、诊断、装配计划与逐项前置检测都已就位，但 guest 本体未接入，
  所以此刻**虚拟机档一律不可选**（界面会逐项列出缺什么、每项怎么补）。
- **工具通道的外部凭据托管**（当前模块工具不得依赖任何凭据）、模块分发与市场、执行期并行调度的进一步放开。
- 所有未完成项、怎么补与验收标准只有一处权威：[tests/gaps.yaml](tests/gaps.yaml)。

**质量**：`node run-tests.js` 是唯一入口——本机跑 T0（格式 / 编译 / clippy / 依赖重复，零容忍）+ 单元 +
跨平台集成 + 前端冒烟 + 端到端；平台围栏的真机探针由三平台 CI 跑（见 [TESTING.md](TESTING.md)）。

## 怎么用

### 1）起产品

```bash
start.bat                 # Windows（双击或命令行）
node start.js             # 任意平台（macOS/Linux 也可 ./start.sh）
node start.js -webUI      # 直接进本地网页；或在终端菜单里输入 webui
```

首次运行**不需要手工准备环境**：启动层序把工具链收敛在项目内（`platform/`、`.tools/`），
缺 Rust 会先征求同意再装进去。**没有配供应商也能跑**：会用内置假模型把流程演示一遍，并如实告知。
（`demo/` 下的脚本是**真机测试**，另算：没配供应商它们会直接拒跑并告诉你缺什么。）

### 2）登记通道与模型（可选）

在界面里加供应商（端点 + 密钥）与模型，设置核心默认模型；密钥只写进 `.home/providers.yaml`。

### 3）建一个工作

填工作名 → 选形态（单 agent / 协作）→ 选 agent（可以让核心按需求推荐一份名单，**由你确认**）→
协作再写下本次需求。之后就是看它讨论、执行、验收：你可以随时「停止 / 继续」，也能点进任意子会话发言。

### 跑一遍演示

演示是**真机测试**：走真实模型，会真的投喂资料、调工具、核产物。所以脚本开工前先核对条件——
前两个演示要三个模块在清单里、indexer 已构建、登记处有供应商与一个可用的模型（用 `SOLOMNI_DEMO_MODEL` 指定，或用核心默认）；
**代理演示**要登记处有供应商、模型与**核心默认模型**，清单里至少有一个模块或一个已存 agent（代理自己就是核心通道，挑人靠这些事实）。
**条件不齐就打印 `DEMO-SKIPPED` 与怎么补、以退出码 2 收场：不跑，也不用内置演示通道凑一遍。**

```bash
node start.js -webUI
node demo/run-demo.mjs         # 组合式：一个 agent 装三个模块（python / node / C++）
node demo/run-demo-collab.mjs  # 小组协作：三个 agent 各持一份能力协商，走完整条流程
node demo/run-demo-proxy.mjs   # 代理：只跟核心说话，它自己挑人、建子工作、被叫醒；停止即全停
```

C++ 模块要先编译一次（产物不入库），命令与理由见 [modules/indexer/README.md](modules/indexer/README.md)——前置检查会替你确认这一步。

## 它不是什么

- 不是模型或供应商：通道与密钥是产品资源，模型可以任意替换。
- 不是调度常驻进程的运行时：模块不常驻、不待命，只在被交付任务时工作一次。
- 不是常驻服务：模块不常驻、不待命，放进去就出现，移走就消失。
