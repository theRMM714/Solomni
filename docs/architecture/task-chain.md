# 任务链与子会话

> 本文是**协作会话如何从"讨论"走到"交付"的唯一权威**：审查关卡、任务链（依赖图）、子会话、验收与边界语义。

**当前状态：已落地。** 讨论 → 整理（出链）→ 审查关卡 → 链驱动（子会话）→ **节点验收** → 总验收，全部按本文实现。

## 一、形态

主会话（协作）= **编排者**：它自己不跑成员的工具循环，只负责建链、建子会话、推进、验收。

```
讨论（轮流发言，同意粘住，在场者全员同意）
  → 整理：核心 AI 总结讨论 + 出任务链
  → 审查关卡：核心把方案与**建议**交给用户，**用户回一句明确的开工**才推进
    （意图是否明确由核心 AI 判定；模糊的回应不算明确，不开工）
  → 任务链推进：按依赖图分层出**阶段**，同阶段的节点并发（各一个**子会话**），阶段之间串行
  → 验收：节点级 + 全局级；需要用户时暂停，回**主会话**讨论
```

## 二、子会话 = 单 agent 会话

> **会话模型（主/子会话、回合、发言标记、回档同步、压缩）见 [session-model.md](session-model.md)。**
> 该文档已定下"每个在组 agent 一个会话、讨论与执行不分家"的契约（**实施中**）；
> 本节描述的是当前实现（就绪节点各建一个子会话），落地后本节随会话模型一起改写。

- 子会话是**普通单 agent 会话**（独立上下文、转录、围栏），复用全部既有机制；**不新增会话类型**。
- 它**继承父会话的沙箱**（同一共享区 + 该 agent 的私有区）：协作的产物要在一起。
- `SessionMeta` 增 `parent`（谁编排）与 `node`（服务哪个任务节点）；侧栏按**父下挂子**呈现。
- 用户可进入子会话对话干预；子会话的**任务目标**可改（见五）。

## 三、任务链（依赖图，串并混合）

```text
TaskChain { nodes: [TaskNode] }
TaskNode  { id, title, objective, assignee, deps, status, sub_session, acceptance }
```

- **阶段由依赖图派生**（最长路径分层）：无依赖 = 第 1 阶段，其余 = 依赖里最大的阶段 + 1。
  同阶段的节点互不依赖 → **并发**跑；跨阶段**串行**——下一阶段要等本阶段整体验收通过。
  "有一个要等其它全部结束"就是 `deps = [a, b]`，它自然落在下一阶段。
- **节点序号由核心按阶段派生**：第 s 阶段的第 k 个节点 = `n{s}-{k}`（k 按链内顺序）；
  模型给的 id 只用来表达依赖，派发前整体重映射——用户看到的序号因此带前后关系，不靠模型自觉。
- **"并发还是串行"不是两种模式，是同一张图的形状**：核心 AI 只输出这张图。
- 调度器是核心内的**纯函数**（给定链与各节点状态 → 返回**当前阶段**可启动的节点集合），是最该被单测钉住的一块。
- **环必须被如实拒绝**：链是有向无环图，出现环 = 装配错误，不静默丢节点。
- 并发上限用设置里的工作池大小。

## 四、驱动与不变量

- 父会话的推进是**非阻塞一步**：看调度器结果 → 为就绪节点建/复用子会话并派发 → 立刻返回。
- **子会话完成叫醒父会话**：子会话的生成收尾发生在核心线程，在那里标记节点、再推进一步
  （短操作，不占命令队列）。
- 不变量：所有状态变更只在核心线程；子会话的生成在工作线程（与单 agent 同一套 own-and-return）。

## 五、审查关卡与任务目标

- 审查关卡是**核心请用户裁决**（`SessionEvent::Decision`，`kind = plan_review`）；
  核心把"为什么要你定 + 我建议怎么做"说清楚，用户用**自然语言**回一句。
  这两句由核心 AI 给：**建议随方案（`plan`）与节点验收（`node_verdict`）那一次调用一起产出**，
  不额外花调用；没有建议就是空串。
- **由核心 AI 判定用户的意图是否明确**：明确才开工；模糊的回应不算明确，**不开工**——
  它进主会话当反馈，关卡留在那儿等用户（核心不做自动重试、不自己往下推）。
- **改需求不是关卡**：它是会话级动作（`can_update_task` 为真才渲染按钮），用户想改随时点，
  回到需求行、追加新需求，核心按最后一条判定。
- **改任务目标 = 改该节点的任务提示词**（不是用户随口一句话）；改完**不作废**——
  让它跑完，由核心验收按**当前目标**判定；核心若认为链有问题，暂停并回主会话与用户讨论。

## 六、边界语义

| 场景 | 约定 |
| --- | --- |
| 删父会话 | **级联**：先停并删所有子会话 |
| 删子会话 | 该节点标 Failed 并通知用户（链不静默跳过） |
| 回档父会话到审查关卡之前 | **级联删除**子会话 |
| 节点失败 / 超时 | 节点 Failed + 暂停 + 主会话通知（不自动重试） |
| 停止父会话 | 不启新节点；已在跑的子会话各自停 |
| 用户改子会话目标 | 旧产出**不作废**；核心验收按新目标 |
| `create_session` | 当前不做（以后的功能） |

## 七、分期与验收

| 期 | 内容 | 状态 |
| --- | --- | --- |
| 4a | 链模型 + 调度器（纯函数） | ✅ 单测覆盖串 / 并 / 混合 / 环拒绝 / 悬空依赖 |
| 4b | 审查关卡 | ✅ 整理完停在待审（`Pending::PlanReview`，推 `Decision`、快照带同一份）；用户回一句明确的开工才推进 |
| 4c | 子会话 | ✅ 就绪节点各建一个普通单 agent 会话（`parent`/`node`，沙箱锚在父会话上） |
| 4d | 驱动与叫醒 | ✅ 派发到子会话（Web 走工作线程、CLI 与测试同步走）；子会话完成标记节点并叫醒父会话 |
| 4e | 验收 | ✅ **每阶段一次**：本阶段全部跑完后，核心 AI 判这一阶段的产出（够不够下一阶段用，一次调用判完本阶段）；通过才解锁下一阶段；没过就暂停并交用户；全部阶段通过后总验收 → 交付 |
| 4f | 会话树 | ✅ 侧栏按 `meta.parent` 把子会话缩进挂在父会话下（`HistoryView.parent`） |

**验收没过的处置**：**重派哪些节点由核心的结论决定**——只把核心判"没过"的那些退回待办（同阶段里
已经通过的节点保持"已通过"，不整阶段重来），父会话置 `Pending::NodeBlocked` 并如实告知是哪几个；
用户点「继续」→ 重派这些节点（子会话复用，agent 能看到自己上次的产出）→ 再验（仍按阶段）。
结论里写了个本阶段不存在的 id、或漏了某个节点的结论 = 这次判定用不了：核心会**要求重填**（如实通知，
一直重填、不设次数上限——用户用「停止」控制流程），绝不静默丢掉一条判定、也不假装这一阶段过了。
**总验收的返工同样是定向的**：`checklist.items[].rework` = 要返工的**节点 id**（从提示词里那张
"节点 id — 负责人"表里选）；没过（fail）的条目必须填它——核心只把这些节点退回待办，用户点「继续」后
只重派它们（不交付）；漏填或填了表里没有的 id 同样要求重填。
