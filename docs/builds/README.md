# 构建：按模块声明把产物编出来

> 单元入口。[ARCHITECTURE.md](../../ARCHITECTURE.md) 定分层，[MODULE_SPEC.md](../../MODULE_SPEC.md) 的「构建」定模块作者契约，
> 逐文件职责见 [unit-map.md](unit-map.md)。

## 它做什么

模块在 `module.yaml` 里声明 `build:`（命令 + 构建期能力 + 是否要网络）。构建能力在**目标环境**里执行那条命令，
把产物编进模块目录，然后**复验入口**——命令跑通不等于入口真的能跑。

两个调用方：

- **创建会话前**（自动）：本次名单里的模块，若声明了 `build:` 且 `build-state.target` 不是目标环境（或入口不在场），
  就先在目标环境编一次；编成继续建，编不成则**创建失败**并如实报原因（不留下会话、不落构建状态）。
- **`solomni --build=<模块 id> [--guest=<虚拟根>]`**（手动）：入口在场也按源指纹决定是否重编；给作者与运维的显式入口。

## 语义

| 场景 | 行为 |
| --- | --- |
| 入口在场、`build-state.target` 与目标一致 | 跳过（创建时零成本；手动 `--build` 仍看指纹） |
| 入口在场、没有构建状态（随仓自带产物） | 跳过；无法从状态判断目标 |
| 入口在场但状态是别的目标（如宿主产物进 guest） | 在目标环境重编，编完复验入口 |
| 入口不在场、模块声明了 `build:` | 在目标环境编一次，编完复验入口 |
| 入口不在场、模块没声明 `build:` | 拒绝，指到「自带产物或按模块 README 构建」 |
| 构建期能力缺失 | 拒绝，点出缺哪个能力 + 几条出路 |
| 构建命令失败 / 编完入口仍不在场 | 拒绝，错误里带目标环境与命令输出；**不落状态**（下次重试） |

「入口在场」与创建会话时的入口判据同一把尺子：名字按目标平台的壳解析（Windows 补 `.exe` / `.cmd` …），
跨平台还看文件形式（ELF / Mach-O / PE / 脚本头）。同平台同架构但 CPU 特性不同（宿主 native 产物进 qemu64 guest）
入口判据看不出来——所以缓存命中必须同时看 `build-state.target`。

### 成功口径

**产物是唯一判据**：入口在目标环境里在场且能跑才算编成。命令退出码只当**快速失败信号**——非零即失败；
零退出但入口不在场同样失败（此时错误里明说"脚本可能吞掉了失败"，并附命令输出）。

为什么不信退出码：构建脚本自己会判失败（见 [MODULE_SPEC](../../MODULE_SPEC.md) 的「构建」），但脚本写错
（例如 Windows 的 `if errorlevel 1` 对崩溃码不成立）就会把编译器的崩溃报成成功。产品据此复验产物，
所以误判只会让**归因**不准，不会让失败被当成成功。

## 目标环境

- **本机档**：在宿主上编；围栏由产品给，只写模块目录与 `.vm/build-state/<模块>/`，只读放行项目内基础工具链的安装根
  （编译器要读自己的 libexec / 动态库）。出站网络 = 全局开关与模块 `build.net` 的交集。
  **构建是系统动作，不申请容器身份**（与 `--build` 同一条执行路）：Windows 上按无容器路径跑，
  可达范围仍由围栏规格给出。容器里的工具临时区由围栏准备（见 [kernel](../kernel/README.md)），
  编译器可以在容器里落临时文件；构建本身不走这条路。
- **虚拟机档**：在指定虚拟根里编。起一台**一次性** guest（`isolated`，用完销毁），模块目录**读写**挂进去，
  产物因此直接落回宿主那份；编译能力由 guest 自带（`guest.yaml` 的 `runtimes`）或运行包库提供。
  需要 QEMU 与可用虚拟根；缺了如实拒绝。

## 构建期能力

`build.needs` 里的名字是**目标环境 PATH 上的可执行名**（如 `gcc`）。选包规则与运行能力同一套：

- 本机档：项目内基础工具链（Python / Node / C-C++）优先，其次宿主 PATH 回退，再其次是 `runtimes/` 里的包；
  缺了如实拒绝——「声明不构成保证」。
- 虚拟机档：guest 自带的运行能力优先，其次包库（prefix 的 `bin` 进 PATH、system 的载荷叠写进系统路径）。

## 缓存

状态落 `.vm/build-state/<模块>.json`：`target`（`host` / 虚拟根名）+ `fingerprint`。本机档与各虚拟根**共用一份**，靠 `target` 区分。

源指纹 = 构建命令 + 能力名 + 能力的实际提供者 + 网络开关 + 模块内**全部源文件**（相对路径与内容）；
跳过 `build/`（产物本身）与 `userdata/`（跨任务私有状态，不是源）。指纹一致且入口都在场才跳过重编。

产物写入模块目录（`build/` 在 `.gitignore` 里）；agent 看得见产物，看不见工具链。
