# 会话模型与上下文压缩

> 本文是**"一次工作里有哪些会话、它们怎么对话、怎么同步、上下文怎么压"的唯一权威**。
> 任务链（依赖图、审查关卡、验收）见 [task-chain.md](../collab/task-chain.md)；工具与角色见 [tools-and-roles.md](../tools/tools-and-roles.md)。

**执行席按 agent 一会话**（含同 agent 串行）、**讨论回合开工具循环**（能只读核实、拿不到模块工具）、
**讨论由核心驱动**（泵只决定"该问谁"，成员回合在它自己的会话里跑，核实行与回合标记都落进那个会话；主会话只留"谁说了什么"）。
**agent 会话在第一个回合按需建**。
主会话投影行带 `turn`（回档按回合同步截断）；角色表机制化（工具面与越权校验同出一份表）；压缩：`compact` 工具 + `compacted` 事件 + 发送视图，按模型窗口百分比自动触发。

## 一、形态

一次工作（work）有两类会话：

```text
主会话（议场）      核心的地盘：汇总发言、出方案、挂任务链、验收、交付。
                   它自己不跑成员的工具循环。
每个在组 agent 一个会话   该 agent 在这场工作里的**完整经历**：
                   讨论时核实了什么、答应了什么、自己那些节点怎么做的、用户中途插过什么话。
```

落盘布局（机制口径，全项目只在这里画全）：

```text
session/<工作名>/
 meta.yaml          # 身份与选型：形态、agent 名单（名字 / 人设 / 模块 / 模型）、需求、会话权限覆盖（sandbox）、执行档位（exec 段）
 transcript.jsonl   # 事件流水（留档只追加 rewind；删除 / 恢复整体重写）
 work/              # 本次工作的共享区**主副本**：用户投喂与成品（整棵树只有顶层这一个，agent 只读）
 .work/             # 共享区版本库：内容寻址对象、提交记录、各 agent 的拉取基线、待恢复事务、提交号计数器、跨进程锁（保留名）
 <agent 实例名>/     # 该 agent 的私有沙箱，也是它的**工作副本**（work_pull 落在这里）
 children/          # 子会话（协作派生的执行席、代理建的子工作；可再嵌套）：<父名>--<名字>/
```

- agent 会话**在第一个讨论回合按需建**（名单确认时不预建），命名 `<工作>--<agent>`。
- agent 会话是**普通会话**：独立上下文、独立转录、独立围栏，复用同一套会话机制；**不新增会话类型**。
- **讨论与执行不分家**：同一个 agent 会话先用于讨论、后用于它的节点，上下文连贯。
- **落盘在主会话目录内部**：`session/<工作>/children/<工作>--<名字>/`——位置与 `meta.parent` 同源
  （看位置就知道归属）；`session/` 下不出现与主会话并列的子会话目录，**删主会话就是删一个目录**。
- **可以再往下嵌套**：子会话自己还能有子会话（代理建的协作子工作会派生节点子会话），
  每一层都是父会话目录下的 `children/<名字>/`；查找、列清单、级联删除都按**任意深度**走整棵 children/ 树。
- **整棵树只有一个 `work/`**：不论嵌套多少层，共享区始终是**顶层**那一个（工作根 = 沿 `meta.parent` 走到顶），
  各 agent 沙箱也建在它下面；实例名因此在**整棵子树**里唯一（重名自动带尾号，见 registry 的命名策略）。
- **环境属于顶层工作**：`exec`（档位 / 虚拟根 / 定版）由人建主会话时决定，整棵子树只读继承；
  核心代理建子会话时不能自选环境。**同一 agent 全树只有一份名单**：子会话编辑模块 / 模型时写回这份名单，
  guest 装配按整棵树重新聚合；只改模型 / 权限不重建 guest，改模块 / 环境才重建。
  会话权限是**根 ceiling + 子会话逐层 narrowing**：根写 sandbox.ceiling，子写 sandbox.narrowing；子只能换更低档、只能收窄，父编辑只改 ceiling 并与子 narrowing 求交，不覆盖子收窄。
- **共享区是版本化工作区**：主副本 `work/` 与版本库 `.work/` 都锚在顶层工作上；agent 只写自己的沙箱，
  `work_pull` / `work_commit` 与主副本同步（文件级三方比较），`work_versions` 看三方，`work_resolve` 显式选边，`work_status` 看状态。
  文本、图片、视频与其它二进制都按字节处理（内容流式读写、不整份进上下文；单文件有上限）；
  `work_versions` 给 hash、大小与扩展名媒体类型提示；文本可人工合并后用 `take=local`，图片 / 视频 / 二进制只能选边，不做自动合并。
- **会话权限层**写在 meta.yaml 的 sandbox.ceiling（根）与 sandbox.narrowing（子）：
  四档 profile + 共享区三态 + 逐工具决定；缺省继承 settings.yaml 的 sandbox.defaults；sandbox.policy.deny 是硬底线，
  会话只能追加、不能清空。语义见 [docs/permission/README.md](../permission/README.md)。
- **出站网络是全局开关**（`sandbox.policy.network`）：会话工具、直接模块工具、常驻服务、模块构建共用；
  虚拟机档决定 guest 网卡；本机档 Windows 授 `internetClient`、macOS 放行 `network-outbound`、
  Linux `net=false` 用 seccomp 拒绝非本地 socket（`net=true` 不装网络过滤器，不限制入站/绑定）。
  Windows 只放行公网出站，不授 private network / loopback；Windows 未授权 `windows.write_acl` 时容器不装，网络不生效。
- 侧栏**可见**：agent 会话挂在主会话下（`meta.parent`），用户可进入查看与发言干预。
- 侧栏顺序是**树序**，由核心给出（父会话紧跟它的子会话，深度优先、各自按时间倒序）：
  顺序与缩进是同一件事的两面，各排各的就会出现"子会话排在父会话上面"的错位。
  父会话已被删的子会话如实列在最后，不凭空消失。

## 二、回合（轮）

> **一轮 = 所有"还能发言的人"各发言过一次。**

- "还能发言" = 在组 **且** 未同意 **且** 未离开。已同意/已离开的人本轮不问（同意是粘住的）。
- 一次"发言回合"= 核心把讨论上下文交给该 agent 的会话，然后**等**；它可以在自己的会话里调工具（核实）、
  继续想，**直到用讨论动词表态**。
- **转录永远是核心的活**：子会话从不往主会话写；核心拿到动词才转录主会话并往下走。

### 计数与提醒（讨论阶段）

**模型调用次数没有上限**：子会话继续核实就继续跑，直到模型不再发起调用、或用户点「停止」。
不上"到顶直接收尾"这类天花板——它会把"还想接着核实"误判成"必须收尾"，执行席因此干到一半被掐断。

留下的只有**提醒次数**：这一轮对它提醒过几次（默认 3，可设置）。

- **什么时候提醒**：这一回合结束在**纯正文**（没有用讨论动词表态）时，核心**只注入一条提醒**
  （"你还没用讨论动词表态"，见下"系统消息"）——**不强制**它表态。
- 提醒次数**到顶**：本轮放它过去——主会话如实记一行 **"未回应"**，整轮继续（**不阻塞**）。
- **何时归零**：每轮开始、进入下一阶段，或它给出了讨论动词/回报时。
- **用户主动中止**时不提醒（用户可能正想和它讨论）。用户和它聊完、点上下文「继续上一轮」后，
  它**仍要给出讨论动词**才算发过言。
- 收敛、上限、退出、请教（ask）的判定与 task-chain 一致，只是"问谁"变成"问它的会话"。

### 系统消息

系统注入的东西（提醒、压缩边界、工具围栏降级这类**不是用户说的、也不是模型说的**内容）必须有
**系统消息**这一种转录行，不能在转录与前端里长得像"用户发的"。

- 结构化信号随行落档（`system: true`），呈现层据此换样式，**不靠匹配文本**；
- 进上下文时按它该有的角色进去（提醒是给模型的指令），但**用户看到的是系统行**。

**内容类系统提示是另一种行：`kind: "notice"`。** 它只给人看、**不进模型上下文**，
有会话内稳定 id，能与普通行一样折叠、回档、删除（建组、阶段验收、返工、停止、中断、代理授予/转达…）。
分配点在会话对象里（`AgentSession::note_notice` / `CollabSession::notice`）——和普通行共用一个
单调计数器，落盘、重建、回档因此走同一套账；重建时 `replay_dialogue` 明确跳过它，不产生任何消息。

**不是所有提示都行化**：过程性提示（工具调用形态变更、"末条是 AI 发言"这类提醒）、
工具层确认（放行前的「待确认」、放行后的「确认」）与基础设施故障（落盘失败、线程崩溃、无回应）
保留为**瞬时 `Notice` 事件**：它们的持久事实是裁决卡 / 回答或 meta，不是转录内容；
工具层也拿不到会话的行计数器。它们照样推给在场的前端，只是没有 id、不可回档、**不写 `transcript.jsonl`**：
原始 `Notice` 是瞬时事件，刷新后不该再出现；「停止 / 继续」这类控制动作即使发生在生成期间，也只保留瞬时提示，
真正的持久事实是 `meta.run` 与生成收尾的 `[停止]` 内容行。

**派发行**是系统行里的一种（`system: true` + `task: true`）：核心给某个 agent 派的活。

- 界面上它和别的系统行一样是核心说的话——**不得显示成"用户"**；
- 上下文里它以 **user 角色**转发：派活是一次**回合**，而会话协议要求请求里至少有一条 user 消息，
  一条 user 都没有的请求会被供应商**整条拒收**（全 system 的请求返回 400）。
  讨论席同理——它每次都用一条 user 回合（opener / step）开场。
- 两处口径都随行落档，所以**重建/回放产出发出去的那同一条消息**（见 [四之二](#四之二节点执行只有一条管道)）。

### 会话种类 × 推 / 落

**推是一处、无条件的**（底层收发该做的事）；**留不留由会话种类定**（不由调用点定）：

| 会话种类 | 推 | 落（判定只有一处：`persist_policy_for`） |
| --- | --- | --- |
| 单 agent 会话 | 定稿行 + 短暂事件 | **留**：逐轮的正文/工具/思维链——那是模型上下文的一部分，不留则重启后上下文歪 |
| 协作会话（含**核心自己的操作**） | 同上 | **留**：协议行 + 发言投影 + 核心的工具行/思维链/正文 + 派发/完成/阶段/返工通知——它是派生状态的来源，用户也要对账 |
| **系统会话**（sid 以 `#` 开头） | 同上 | **不留**：一次性动作（让核心推荐 agent、探针、一次性判定），重启后本来就该是空的；它**不进会话表**（`/api/state` 里没有它），所以前端不会为它建标签页 |

短暂事件（`Delta` 增量 / `Working` 运行态 / `ToolCall` 实时工具卡）**任何会话都不落**——
它们只给在场的前端看；`/api/state` 与推来的事件已经把"当前该显示什么"说清。

**上下文用量是独立事件**：`usage` 记录最近一次模型调用的 prompt / completion / total、当时的窗口与"精确还是估算"。
它**不落成转录行、不进模型上下文**，随会话流水落盘（刷新/重建可恢复）；`line` 是这次调用产出第一行的行号，
回档折叠到它之前时这条用量随之失效。`SessionView.context` 是同一份事实的快照，**只给有持续对话的
`Session::Single`**（single / proxy / 协作的 agent 子会话）；协作主会话 `Session::Collab` 没有这个字段。
**shell 状态也是快照**：`SessionView.shell` 取该会话最近一次 shell 的运行槽（命令、scope、cwd、起止、退出码与回执预览），
由工具循环写、状态栏读；它只服务界面，不进模型上下文，也不替代转录里的 shell 工具行。
**裁决卡与回答是例外**：`DecisionCard` / `DecisionAnswer` 按上表落盘（单 agent 与协作会话都留、系统会话不留）——
"用户答过什么"是会话的事实，重启后卡与答案都要在（见"请用户裁决"一节）。

**会话表由后端给，前端不自己造会话**：前端只为 `/api/state` 会话表里"后端说在跑"的会话建标签页，
事件流里出现**不认识的 sid** 一律不动（只置位，等下一次状态刷新把会话表带进来）。
理由：为事件里冒出来的 sid 就地建会话＝前端自己造会话状态；系统会话不是真会话，
它会因此冒出一个多余的标签页，而真会话的记录又会被建重一遍。
于是系统会话推出来的行**没有任何前端动作**：它不在会话表里、也不落盘，就是底层那一次无条件的推。

**历史与实时合流，前端不合并两个来源**：`GET /api/history/{name}` 一次给全盘上转录 + 事件台上它之外的尾巴，
并给出合流时的头部序号当**水位**；此后 `seq ≤ 水位` 的批次丢掉、之上的按序 append（见 [contracts.md](../presentation/contracts.md)）。
判据是结构化相等而不是行 id——`node_started`/`report` 与瞬时提示没有行 id（内容类系统提示已经是
`transcript` 里的 `notice` 行，有 id）。
**回档会推进重置水印**：水印之前的批次已被盘上转录取代，`live` 只取水印之后；前端收到 `rewound` 时清空重建。

**行身份是结构化字段**：一行带 `speaker`（谁说的）/ `verb`（动词：say / agree / 需求 / 开始…）/
`kind`（`msg` 模型发言 / `user` 用户说的 / `system` 系统注入或核心自己的行 /
`notice` 内容类系统提示 / `tool` 工具行 / `round` 轮次分隔行），**正文里不带 `[谁:动词]` 标签**。`LineView::render()` 是"字段 → 文本"的**唯一**拼法：
提示词里的转录（`{{transcript}}`）与回放比较都读它；呈现层按 `kind` 换样式、按 `speaker`/`verb` 显示身份，
不解析文本（见 [contracts.md](../presentation/contracts.md) 的推的事实）。

## 二之二、谁驱动谁（实现形态）

> 契约要定死这一点，否则会出现两套"谁驱动谁"的说法。

**讨论不由泵自己调模型，而是"泵只决定、核心驱动"**——与任务链的节点派发**同一套路**。

理由是会话归属：生成期间协作会话被**移出核心表**（own-and-return），它碰不到表里的 agent 会话；
而 agent 会话必须留在表里，用户才能随时进去发言。所以**驱动权归核心**（它同时看得到两边）。

### 看不见的回合：运行态与逐片外送

成员回合跑在**它自己的会话**里，主会话在整回合里一个事件都收不到。所以核心要主动交代两件事，
否则用户看到的界面就是"整回合不动、只有手动刷新才同步"：

- **逐片外送**：成员回合与**核心操作**的正文都逐片推 `Delta`（沿用"到 `{` 就截住"的分片规则——信封绝不当正文流出），
  核实行实时推 `ToolCall`。外送目标是**该 agent 自己的会话**（打开它的标签页就能看到它逐字在说、在读文件）。
- **逐轮定稿**：成员回合与单 agent / 节点回合跑的是**同一条轮循环**（`engine::converse_with`；
  这一回合的参数收在 `session::TurnRun`：身份、本回合工具面、本回合提示、表态约定、回合号）。
  一轮跑完就出这一轮的行（`engine::build_round_lines` 是**唯一的行构造点**），
  那批行**同时入它自己的事件台与落盘**——只落盘的话，那个标签页的流式块永远等不到替换它的那一行，
  正文一直挂着闪烁光标、看着像"还在流式"。思维链随该轮的权威行保存（工具轮没有正文时挂到工具行上），
  流式结束或重放后仍可查看；没有定稿的停止/错误分片在空闲事件到达时撤下，不冒充转录。
  主会话那份是**投影**（`feed_with` 只投影"谁说了什么"），与子会话各一份、互不重复。
- **运行态的唯一真相是事件**：`SessionEvent::Working { agent }`（短暂、不落盘，`None` = 空闲）
  在"要问谁 / 这条会话开始生成"时推带名字的那条、收尾推空闲；**主会话与子会话各推各的**——
  子会话若只靠"有增量=在跑"推断，收尾就永远清不掉：那个标签页一直显示"正在工作"、按钮一直停在「停止」。
- **`/api/state` 的 `running` 是对账副本**：前端只在"本页对这条会话还没有实时知识"时用它
  （刚刷新页面、事件台裁掉一段后的重连、别人建的会话）；收到过 `Working` 之后只认事件——
  一次迟到的轮询不会把已经收尾的回合标回"在跑"；事件台出现补不齐的缺口时实时知识作废、退回对账。
  前端的按钮切换（发送/上下文继续 ↔ 停止）、占位动画（"正在工作：某某"）都读这条运行态；
  此外"本页发出的命令还在途"也算忙——那是本地事实（防重复提交），与服务端运行态不是一回事。

### 落盘的运行态：停止 / 关闭

"这一刻在不在跑"是短暂事件（`Working`）；**"这段工作还该不该继续被驱动"是持久事实**，
落在 `meta.yaml` 的 `run` 段（`active` / `stopped` / `closed`，缺省 `active`）：

- **`stopped`**：已停止。此后的**派发与唤醒一律被拒**（"取会话去生成"那道闸 `Conductor::dispatch_gate`
  两者都拦）；正在跑的那次会被**级联停掉**。用户点「启用」把它解冻回 `active`——
  启用是显式的恢复动作，只恢复会话（含虚拟机 guest），**不产生模型调用**。
  真正"接着走"由上下文继续负责（见下）：单 agent 上一轮被打断时给「继续上一轮」，
  协作泵没走完时给「恢复协作」；没有断点就不显示。
- **`closed`**：终态。不能再被派发、唤醒或继续；关闭时整棵子树里还有在生成的就整条拒绝
  （先停），不留半个状态。
- 判据只有一处（`SessionMeta::dispatch_refusal`）：转达、观察、控制与叫醒都问它，不各写一份。
- 重启 / 回档后照样成立（它就是 meta 的一部分，不属于"这一刻"的短暂态）。
- **启用 / 继续分开**：历史回放只读，只有「启用会话」；它由 `activate_session` 走两段式
  （核心准备 → 调用方线程起 guest → 核心提交），不跑模型、不写转录。启用后 `SessionView.continue`
  才决定是否显示上下文继续；前端不自己判断末条或协作泵。
- 用户点「停止」= 先把整棵子树落成 `stopped`、再中断正在跑的生成（**顺序不能反**：反了的话，
  被停会话收尾写的那条"这一轮结束"会先把父会话叫醒）。
- **停止要取消在途请求，不是只置一个标志**：LLM 出站适配器在等待响应/下一个数据块时轮询取消位，
  置位即关闭连接；生成循环在解析载荷、执行任何工具**之前**再检查一次取消。已流到一半的 tool_call 不执行。
- **模型调用超时分三层**：连接 10 秒；首响应/首个数据块用设置里的预算（`llm_timeout_secs`）；
  流已经出数据后，两个数据块之间最多等 120 秒，收到任意字节（含 SSE keepalive）即重置。
  正常流式没有总时长上限——只有真正等不到下一个字节时才中断；非流式调用仍把这份预算当整次调用的上限。

### 请用户裁决：一条通道，消息 + 选项

**任何需要用户裁决的 yes/no 都走同一条通道**：核心请用户定的事（名单确认 / 开始讨论 / 请教 / 方案待审 /
节点没过）、工具级确认（`ask` 粒度）、以及工具层自己发起的一类（例如围栏这一环装不上）。
后端只有一份实现、前端只有一种渲染。

> **接入范围**：核心各关卡（请教 / 代拟确认 / 开始讨论 / 方案待审 / 节点没过）与**工具级确认**（`ask` 粒度）
> 都走**卡片 + 选项 + 一条回答命令**，卡、回答与作废都落盘，重启按转录**整队重建**，两端按选项渲染；
> 同一会话一次只问一条——并发发起时后到的**排队**，界面与快照都带着"谁在等、前面还排着几条"；
> 用户按停止（或会话关闭）时**整队作废**，等待方按"停止 = 拒绝"解开；
> 回答与「停止」同一条直路——回答**先落定**（校验 + 出队 + 记一条回答），处置再脱离调用方跑。
> **工具层与围栏也接进来了**：经 `kernel::ports::AskUser`（推一条问题、**阻塞**等一个选项 id）走同一条队，
> 构不出可用选项时**不发起裁决**，改为停掉这个会话 + 落一条警告。
> **没人答时的收场**：发起方在那一问上声明一个**自己卡上的选项 id**（`Ask.on_unanswered`；不写 = 不执行），
> 通道只在"没人答"时用它收场；"用户答的 / 按声明收场的 / 没人答的 / 用户停止的 / 构不出选项的"如实分开，
> 发起方只看"照哪个选项办"。**停止（整队作废）不套用默认项**——停止不能被当成放行。

**形状**（`DecisionCard`）：`id`（会话内唯一、稳定）+ **信封**（谁在问：核心 / 某一席 / 工具层）+
**消息**（`title` / `body` / `detail`）+ **选项**（`{id, label}`，有序）。
渲染层**只认这四个字段**，不认识业务含义：把消息画出来、把选项画成按钮，点了就把**选项 id** 发回去。

- **消息与选项由发起方（底层）给**：怎么问、几个选项、每个选项做什么都由发起方实现；通道不解释内容。
- **选项行为靠稳定 id 映射**：文案可改、可本地化，id 是契约（回答按 id 分派，改文案不改行为）。
- **没有"不可选"的选项**：**禁止置灰**——置灰会让会话卡在那里没人点得到东西。选项集里每一条都必须是
  真能执行的；构不出可用选项时**不发起裁决**，改为**停掉这个会话 + 落一条警告**（写清哪一环做不下去、
  要补什么）。卡片一旦推出，选项集**不可变**：要改只能作废这一条（界面如实标"已作废"）再推新的，
  绝不静默改写用户已经看到的选项。
- **必须阻塞**：发起方阻塞等回答，**不设超时**——不点不继续。终止只有三件：用户回答 / 用户按停止
  （解成**拒绝**，不是放行）/ 会话被删除；停会话时**整队作废**，等待方一律按"停止 = 拒绝"解开。
- **队列**：同一会话同时只问一条——**多席并发按先来后到排队**，**只有队首那张可见、可答**
  （排在后面的还不能答：它的答案会被"卡号不是队首"挡下）。界面与快照都让"谁在等、前面还排着几条"可见：
  推的卡片事件与 `/api/state` 的 `pending` 里都带 `waiting`——队首之后还在等的那几张，按先来后到，
  每条带**自己的卡号与这一关的重建材料**（界面只看它的信封与标题，材料归机制）。
- **回答只有一条命令**（动作 `answer_card`，带上卡片 id + 选项 id（可带附言））；
  回答要**校验选项 id 属于当时那张卡的选项集**（防旧卡的答案被用来放行新的请求）。
- **落盘**：卡片（`DecisionCard`）、回答（`DecisionAnswer`：谁答的、选了哪个 id、附言）与
  **整队作废**（`DecisionVoid`：作废了哪几张、为什么）都按上表落盘；
  `/api/state` 的 `pending` 是同一份事实的快照形态（重启后由转录重建）。
  **已答过的不得重问**；作废过的也不复活（那一关还挂在状态上时，`继续` 才**续一张新卡**接着问）。
  工具层那一类（`tool_ask`）与工具级确认一样**不重建**：它等在工作线程上，重启后那个等待方已经不在。
  会话被删除时整条队随会话一起没了——等待方与转录都不复存在，没有"留着作废记录"的地方。
- **落地的形状**（线格式）：卡是 `{id, envelope{role,name}, message{title,body,detail}, options[{id,label}]}`；
  推的事件与快照的 `pending` 是**同一份 JSON**（多一个 `type: "decision_card"`、`gate`、机制载荷与
  `waiting[{id,envelope,title,gate,payload}]`），回答是 `{type:"decision_answer", card, by, option, note}`，
  整队作废是 `{type:"decision_void", cards[], reason}`。选项 id 是契约（改文案不改行为）：

| 关卡 | 选项 id |
| --- | --- |
| 请教 | `ask_reply` |
| 代拟名单 | `slate_confirm` / `slate_cancel` |
| 开始讨论 | `begin` / `begin_allow` |
| 方案待审 | `plan_start` / `plan_say`（先说一句，由核心判定明确性） |
| 节点没过 | `node_rework` / `node_say`（同上） |
| 工具级确认（逐工具 decision=ask） | `allow` / `deny` / `allow_turn`（`allow_turn` = 本轮剩余 ask 不再问，不落盘、不改 reach） |
| 工具层提问（围栏这一环装不上，`gate = tool_ask`） | `fence_unfenced_once` / `fence_abort`（见 [docs/kernel/README.md](../kernel/README.md) 的「围栏落点：必要与可选」） |
- **没人答时的收场**：由**发起方**在自己那张卡上声明一个**选项 id**（`Ask.on_unanswered`）——通道不解释它的
  含义，只在"没人答"时按它收场，并如实标为"不是用户答的"；不声明就按 fail-closed（这一趟不执行）。
  **"没人答"与"用户停止"是两回事**：停止 = 拒绝，不套用默认项。"没有可选项 = 停会话 + 落警告"是另一件事，两个都要有。
- **代理转达不替用户猜**：`send_session_message` 要代答就**显式给选项 id**（`reply`）；给不出就不作代答、如实记一条，
  那一步按发起方自己的声明收场——绝不"取第一个选项"（围栏卡的第一项正是"无围栏跑一次"）。
- **不做跨会话的"记住这个决定"**：只保留"本轮不再问"（不落盘）。要"记住"另立设置项——
  否则裁决对象会变成策略载体，与 `capabilities/permission/` 那套裁定重叠。
- **建议由核心写**（随产生这一关的 `plan` / `node_verdict` 调用一起产出，不另花调用），它是消息的一部分。

**回答怎么落进业务**（处理仍归发起方）：

- **请教**：用户的话进**主会话转录**（所有成员下一回合都看得到），不单独转给发问的成员；
- **方案待审 / 节点没过**：由**核心判定意图是否明确**——明确才开工 / 放行，模糊就不开
  （他的话进主会话当反馈，关卡继续等着，核心不自动往下推）；
- **工具级确认**：`allow` / `deny` / `allow_turn`（后者 = 本轮剩余 ask 不再问，不落盘、不改 reach）；
- **围栏这类底层**：按选项做它自己的事（例如"本轮无围栏跑一次"）。
- **改需求不是裁决**：它是会话级动作（会话视图的能力位 `can_update_task`），用户自己点；
  没有"本次需求"的会话**根本不渲染**这个按钮，会话工作中不可点。

### 泵的状态机

泵按步推进，可暂停、可恢复：

```text
泵的每一步只做三件事之一：
  AskMember { agent, msgs }   该问谁、给它什么上下文（本回合的讨论上下文）
  Notice/事件                  如实外送（轮次边界、越权、沉默…）
  Done / AskUser / Interrupted 终态
```

### 一步的完整序列

```text
1. 核心：take_collab(sid)                   协作会话移出表（own-and-return，不破不变量）
2. 核心：泵推一步 → AskMember { agent, msgs }
3. 核心：put_collab(sid)                    先放回，腾出手
4. 核心：take_single(<工作>--<agent>)       该 agent 的会话移出表
5. 核心：跑这一回合（TurnRun：动词 + 只读工具面）  与单 agent 同一条轮循环，见"逐轮定稿"
6. 核心：put_single(...)                    放回（转录增量落盘在它自己目录里）
7. 核心：投影 → 主会话追加"该 agent 的发言行"（带 turn 标记）
8. 核心：回到 1，直到泵给终态
```

- **回合标记**：第 5 步在该 agent 的会话里写一行 `[回合 tN｜第 M 轮]`（**系统行 + 系统消息**：
  不是谁说的，回档按同一口径还原）；第 7 步投影出来的主会话行带 `turn: tN`——
  两边同一个 id（回档同步靠它，见五）。
- **核实行**（只读工具的调用）落在**该 agent 的会话**里：与单 agent 的工具行同一形态，
  由同一条轮循环逐轮产出。
- **用户进 agent 会话说的话**：下一回合它自己就带着（就是同一个会话），不需要额外同步。

### 不变量

- 任何时刻**只有一个**持有者：要么核心表里、要么在跑的那一步手里（与 own-and-return 一致）；
- 主会话状态的改写**只有核心**做（泵只产出"该说什么"）；
- 一轮的边界不变：**所有"还能发言的人"各发言过一次**（见二）。

## 三、发言投影与标记

成员的**发言发生在它自己的会话里**（它调用讨论动词），由**核心投影到主会话**——主会话状态的改写只有核心做。

两边用**同一个回合 id** 对上：

| 落在哪 | 记什么 |
| --- | --- |
| agent 会话 | 该回合开头一行标记：`[回合 t17｜第 2 轮]`；其后是这一回合的工具调用与最终发言 |
| 主会话 | 投影出来的发言行带 `turn: t17` |

于是"这条发言对应它在自己会话里做的那些事"是**可跳转的事实**，回档也有确定算法（见五）。

讨论阶段产生的行（核实行、回合标记、发言）只落进该 agent 自己的会话与投影行，不写共享区。

## 四、工具面按回合给

同一个 agent 会话，**按回合**给不同的工具面：

| 回合 | 工具面 | 为什么 |
| --- | --- | --- |
| 讨论回合 | `read` / `search` / `list` + 讨论动词（say/agree/leave/ask） | 讨论只做**核实**（资料齐不齐、脚本在不在、README 怎么说）与分工；**不产出成品** |
| 执行回合 | 全工具面（文件域 + 该 agent 的模块工具） | 干活发生在执行回合，产物可追溯到节点、可验收 |

- **模块工具只在执行回合给**：讨论回合拿不到"干活"的手段——不是"被拒绝"，是**没有**。
- **这一份工具面是随回合注入的**：核心查"这一回合的身份能用的工具"，把那一份（说明 + 参数）作为一条
  系统消息放进该回合的上下文（原生通道同时用它做工具声明）。**整本工具总表不进提示词**——列了必然被拒
  的工具等于请模型去撞墙（细则见 [tools-and-roles.md](../tools/tools-and-roles.md) 二）。
- 角色表（`systools/roles.yaml`）声明的工具面**由机制执行**：发放（提示词块与原生声明槽）与越权校验
  同出一份表，代码里不另写名单（见 [tools-and-roles.md](../tools/tools-and-roles.md) 三）。
- **派发三类来源同一条路径**：这一回合的工具面里，系统工具走 `ToolExec::run_builtin`，模块工具走
  `dispatch_external`，**核心自有工具**（代理工具等）问注入的 `ToolHandler` 谁认领它——三类同一条路径
  （`kernel/ports.rs` 的 `ToolHandler`，见 [ARCHITECTURE.md](../../ARCHITECTURE.md) §二）。加一类工具只注册一个 handler，不改循环。

### 四之一、会话参数与对话分开

一个 agent 会话里有两类东西，**不放同一个地方**：

| | 是什么 | 放哪 | 何时进请求 |
| --- | --- | --- | --- |
| **会话参数** | 身份（agent 名 + 模块能力包）、工作环境（本环境写法的根目录）、调用约定 | `SessionParams`（结构化字段） | **每次调用现渲染**成一条系统消息 |
| **对话** | 用户说了什么、模型答了什么、调了什么工具 | `dialogue: Vec<Msg>` | 原样带上 |

请求由**唯一一处**装配（`engine::assemble`）：`[身份][本回合工具面][对话…][本回合提示]`。为什么这样分：

- 参数是**派生**的（登记处 + 提示词册 + 工作区路径）。把它渲染成"第 0 条消息"存进会话，就等于让参数冒充对话——
  回档要单独照顾那一条、压缩要给它留偏移、改一个参数（例如登记处里的工具形态）还得把整个会话从盘上重建；
- 分开之后：`rewind(0)` 就是**对话清空**；压缩只算对话的字符数；改形态只改参数里的一格，下一回合自然生效；
- **"回放与实时产出同样的消息"只约束对话本身**——对话是事实，参数是派生。

## 四之二、节点执行只有一条管道

一个节点的执行回合是**核心的能力**，不是前端的能力：核心把任务提示词作为**派发行**注入该 agent 的会话
（`note_task` / `dispatch_task`：界面上是系统行，上下文里是 **user 角色**，见上"系统消息"），
再由生成线程跑该会话；CLI 与 Web 只是各自"点火"（`drive_node` / `prepare_node`），**不各写一套派发**——
同一件事两处实现必然一处对一处错（例如把核心的任务提示词当成用户发言，或把派发写成 system 角色、请求里一条 user 都没有而被供应商拒收）。

派发的生成**跟随设置里的流式开关**：节点在界面上同样逐字出（`llm_opts(true)`）。

## 五、回档：三种模式 + 工作级标记

回档的载体是**标记**（写进转录的 `rewind` 事件），不是"删掉就算"。用户在某一行的
「回档到此处」上二选一：

| 模式 | 转录 | 行 id | 共享区 |
| --- | --- | --- | --- |
| **留档** | 追加 `rewind{mark,mode:archive,before,from,commit,after}`；活动窗口 = `id<before` 或 `id>=from`，文件字节全留 | 新行从全量最大 id + 1 续号，被折叠的行 id **永不复用** | 物化到 `commit`（按行锚算出的提交点），提交历史保留 |
| **删除** | 真的把文件重写到 `id<before`（不留标记） | 同上 | 物化到 `commit` 并**丢弃**该点之后的提交 |

**恢复**（折叠分界上的按钮）：在该标记记录处截断转录——标记与它之后的一切（含留档期间的新工作、
以及更晚的标记）真的删掉；共享区回到标记记录的 `after`，并丢弃 `after` 之后的提交。

**回档也是事件台的一等事实**：三种模式成功后，核心为每个受影响会话推一条瞬时 `rewound`
（载荷 = 回档后的活动视图），并把该会话的**重置水印**推进到这条事件的序号。`history.open` 的
`live` 只取水印之后的事件；前端见 `rewound` 清空当前视图并按视图重建。这样刷新/多端不会再
把回档前的旧批次当成实时尾巴，也解释了"重启后消失、刷新却还在"的差异（事件台是内存日志）。

跨会话同步：主会话回档时，**整棵子树**（子会话、孙会话……）按同一个**回合 id** 收窗——每个会话截到
"最后一个 `turn ≤ T` 的行"，并写同一个 `mark` id；恢复时按这个 id 在各会话里找到标记并一起截断。
正在跑的会话跳过（它自己的收尾会落盘），但共享区保住它的提交。

**按行精确物化共享区**：每个提交记录带 `(agent, line)` 锚（用户投喂锚在主会话当时的行号，agent 提交
锚在它自己会话的行号）。回档时按"各会话的保留行"逐个提交比对，取最后一个"所有锚都还没越过保留行"
的提交点再物化；删除 / 恢复额外丢弃不再可达的提交。行锚由每席的 `MemberTools.line` 随转录推进，
经 `ToolCtx` 交给工具执行者（`work_commit`）。

被折叠 / 被截断的行不进发送视图，也不进压缩摘要的输入；`truncate_events` 是"活动窗口"的唯一算术，
界面按 `rewind` 事件画折叠分界（见六）。

## 六、上下文压缩

> **压缩改的是"发给模型什么"，不是"留下什么"。转录永远完整，旧内容用户照样能查看。**

### 谁压

**agent 自己压**：核心把该会话的上下文发给该 agent，只给一个工具 `compact`，提示它写下 summary。
系统**不替它总结**。

### 怎么落档

- 新增事件 `compacted { up_to: 行号, summary: "…" }` 进**转录**；
- 发送视图变成 `[system] + [摘要] + 摘要之后的行`；`up_to` 之前的内容**不再发给 agent**；
- 重启/回档按 `compacted` 事件重建发送视图；
- 界面显示**压缩分界**（"已压缩到第 N 行"）与**摘要本身**；旧内容留在上方可查（默认折叠、可展开）。

### 多次压缩 = 滚动摘要

第二次压缩的输入是"**上一份摘要 + 之后的新内容**"，输出**一份**新摘要。
无论压多少次，发送视图里永远只有一份摘要。

### 触发

| 方式 | 说明 |
| --- | --- |
| 自动 | 每次模型调用后看该次调用的 token（优先供应商回的 `usage` 的 total；拿不到按字符估算，**界面标注"估算"**）；超过 `模型窗口 × 阈值%` → 下次调用前压一次 |
| 手动 | 输入框 `/compact` 立即压一次 |
| **不可自助** | agent **不能**在普通回合自己调 `compact`：压缩只由**系统阈值**或**用户**发起（行为可预测） |

### 设置

- `models.yaml`：每个模型可声明 `context`（窗口大小）；填 0 / 留空 = 用户不填，自动压缩按 128K 兜底；
- `settings.yaml`：`compact_at_percent`（默认 70）。

### 压不动就如实说

agent 没给出摘要（没调工具 / 调用失败）→ 记一条通知（"压缩没成功：…"）并**继续用完整上下文**；
用户看得到、能再试。**不静默降级、不假装压过**。

### 通用性

压缩是**所有会话通用**的能力，**单 agent 会话同样适用**；代理会话也是 `Session::Single`（一条持续对话，
窗口取核心默认模型），压缩与状态栏用量同一套。协作主会话没有一条持续发给模型的对话，不显示上下文用量。

## 六之二、思考强度（会话级）

- **一个工作一个值**：写在 SessionMeta.thinking（工作根持有）；子会话沿 `meta.parent` 共享同一个档位，不各存一份。
- **作用范围**：只作用于**对话生成**——单 agent 的发言、代理会话的核心对话、协作成员的回合。
  核心内部编排（拟名单 / 裁决 / 验收 / 摘要）保持供应商默认：它们不是"这一场对话"，不该跟着用户拉高成本。
- **解析**：会话档（`SessionMeta.thinking`）优先，其次模型的 `thinking.default`；都没有 = 不发思考参数。
  模型没登记会话选的档 = **切换时拒绝并列出模型**，生成时同样如实报错（不静默降级）。
- **入口**：状态栏的「思考」chip 与配置页的同一选择器都走 `set_thinking`；生成中拒绝切换。
  写在工作根 meta 上，切换后整棵子树的会话从内存丢掉、下一次访问按新档重建。
- **改登记处**：映射从 `models.yaml` 现解析；下一次生成就用新映射。删掉一个仍被旧会话选中的档，
  那条会话的下一次生成会报"模型未登记该档"，由用户换档——不自动替代。

## 七、边界语义

| 情形 | 语义 |
| --- | --- |
| 同一个 agent 的多个节点 | **串行**（一个会话一次只能跑一轮）：派发时按"该 agent 已有在跑的节点 / 本轮已派过"跳过，下一轮推进再派（`spawn_ready_nodes` 的 `busy`/`taken`） |
| 不同 agent 的节点 | 照旧可并发 |
| 删主会话 | 级联：按 `meta.parent` 收集整棵子树，**先子后父**撤围栏授权 → 移出内存 → 删目录；子树里任一节点在生成中则**整体拒绝**（不删到一半） |
| 删 agent 会话 | **不允许用户单独删**：`HistoryOps::delete`（经 `Conductor::history_delete`）如实拒绝，理由"由核心管理，删父会话会一起删掉"；内部的 `session::History::delete` 仍是纯存储机制 |
| 停止主会话 | 不启新节点；已在跑的 agent 会话各自停 |
| 停止**代理会话** | **相关会话一起停**（按编排归属级联）：用户点的那一下就是"全停" |
| 用户进 agent 会话发言 | 正常单 agent 一轮；它下一次发言会带上这段（讨论里能影响它），此后仍要用讨论动词表态 |
| 用户主动中止 | 计数**不再工作**（不注入提醒）；用户可能正想和它讨论 |
| 生成中的控制按钮 | 「继续」在核心调用 / 模型输出阶段**变成「中止」**——用户要能随时停，而不是只能等 |
