# 会话模型与上下文压缩

> 定位：一次工作里有哪些会话、它们怎么对话、怎么同步、上下文怎么压的唯一权威。
> 效力：规范｜核对：2026-11-25｜依据：`src/units/business/agentloop/domain/session.rs`

## 适用与判据
- 会话形态、回合、派发、回档与压缩以本文为准（`docs/session/session-model.md`）。
- 违反由 `src/tests/session/` 与 L4 端到端判定。

## 一、形态
- **执行席按 agent 一会话**（含同 agent 串行）、**讨论回合开工具循环**（能只读核实、拿不到模块工具）、**讨论由核心驱动**（泵只决定"该问谁"，成员回合在它自己的会话里跑，核实行与回合标记都落进那个会话；主会话只留"谁说了什么"）。
- **会话类型是落盘的声明，不是分支**：建会话时把类型表里那一条解析成 `SessionSpec`（`kind` / `name` / `loop_id` / `role` / `flows` / `auto` / `sources` / `system_tools`）写进 `meta.yaml`，之后装配只看这份声明——有流程就按流程装配，没有就一个 agent 直接轮循环（`spec.driven()`）；代码里没有「形态枚举」，也不按 id 分支（「整块交给核心」看 `auto`，不看名字）。类型 id 同时是命令与落盘用的词（ASCII），`name` 只给界面显示，`hint` 是选类型时的一句说明。
- **会话类型是数据**：一个会话类型就是一串流程 id，声明在 `systools/profiles.yaml`（自带 single / collab / proxy 三条；`flows` 为空 = 没有流程、直接轮循环）。每条写清 `id`（命令与落盘用）、`name`（界面显示）、`hint`（一句说明）、`flows`、`auto`（这个类型整块交给核心：没有名单也没有需求）、`agent_visible`（**agent** 能不能用 `create_session` 建它；默认 false = 只有人经呈现层能建，人的入口不受它限制）、`sources`（挂哪几个工具来源：`agent` / `module` / `loop` / `workspace` / `profile`）、`system_tools`（系统工具 id，建会话时展开进 `meta`），以及**没有流程时**坐的静止段 `loop`（如 `standard` / `proxy`，解析成它唯一那个角色位）。**角色与角色位不在这里报**：一个流程段由哪些角色出演（`core: true` = 核心通道，不进成员表；其余是成员角色，角色位各报 `min` 员与它交的机制动作）是段自己的声明，在 `systools/loops.yaml` 的 `loops`（新增流程段在那里加一条，写了 `builder` 的才能当流程；角色本身在同文件的 `roles`）。装配期校验：id 唯一且不含空白、流程已注册且不重复出现、没有流程的类型要有静止段且它不能是流程段、有流程的类型不该再声明静止段、每个流程至少各有一个核心角色与成员角色、角色位引用的角色在册且它交的动作都在工具总表里；各流程成员角色位人数取最大折成 `min_agents`：建会话时人数不够就直接拒绝，代拟名单由流程在建组时判（跨表规则在 `src/units/business/session_model/domain/decls.rs` 的 `SessionDecls::validate`，装载在 `src/units/business/session_model/detail/yaml_decls.rs`）。
- **形状只由类型表定**：没有现拼流程的旁路——`create_session` 的 `kind` 必填，表里没有的类型直接建不出来（`Work::create` 报「会话类型表里没有「…」这个类型」，`src/units/business/work/service/create.rs`）。两扇门共用同一份类型表，但收窄面不同：**人经呈现层**只按「表里有没有」判；**agent** 的 `create_session` 只收 `agent_visible: true` 的类型（`catalog_agents` 的 `scope=types` 也只列这一组，`src/units/business/proxy/service/proxy.rs` 的 `resolve_new_session` 按 `catalog.kinds` 校验）。
- **复合流程按段推进、按段恢复**：一条类型的多个流程段由 `Sequence` 串起来，前一段收尾就把产物（`Artifact`）原样交给下一段并把行号接上；每推进一段写一条 `kind = stage` 的落盘事实（`seq[i]`、切点行号、交出的产物），重建时据此**只造起跑点之后的段**，当前段只拿切点之后的转录窗口（`src/units/business/turn_state/domain/stage.rs`、`src/units/business/turn_state/domain/sequence.rs`、`src/units/business/turn_state/domain/flows.rs`）。产物种类与本段 `produces` / 下一段 `accepts` 对不上就停在原地并记一条提示，不静默推进；进度事实缺失或段表变了（事实指向的段不在了）就退回第一段重推。
- **agent 会话在第一个回合按需建**。
- 主会话投影行带 `turn`（回档按回合同步截断）；工具面由会话类型挂的工具来源合成（来源各自交 id，装配期去重成面）；压缩：`compact` 工具 + `compacted` 转录行 + 发送视图，按模型窗口百分比自动触发。

- 一次工作（work）有两类会话：

```text
主会话（议场）      核心的地盘：汇总发言、出方案、挂任务链、验收、交付。
                   它自己不跑成员的工具循环。
每个在组 agent 一个会话   该 agent 在这场工作里的**完整经历**：
                   讨论时核实了什么、答应了什么、自己那些节点怎么做的、用户中途插过什么话。
```

- 落盘布局（机制口径，全项目只在这里画全）：

```text
session/<工作名>/
 meta.yaml          # 身份与选型：形态、agent 名单（名字 / 人设 / 模块 / 模型）、需求、会话权限覆盖（permission 段）、执行环境声明（sandbox 段）与事实快照（facts 段）、工作台声明（workspace 段）
 transcript.jsonl   # 事件流水（留档只追加 rewind；删除 / 恢复整体重写）
 work/              # 本次工作的共享区**主副本**：用户投喂与成品（默认位置；外部绑定时不存在）
 .work-root         # 外部工作区绑定的布局投影（根会话才有；权威在 meta.yaml 的 workspace 段）
 .work/             # 共享区版本库：内容寻址对象、提交记录、各 agent 的拉取基线、待恢复事务、提交号计数器、跨进程锁（保留名）
 <agent 实例名>/     # 该 agent 的私有沙箱，也是它的**工作副本**（work_pull 落在这里）
 children/          # 子会话（协作派生的执行席、代理建的子工作；可再嵌套）：<父名>--<名字>/
```

- **目录保留名**（`work` / `children` / `.proxy` / `.work` / `.work-root`）的名单在 `systools/names.yaml`：布局一改就改表，代码里不硬编码。
- **缺省名由后端派生**：没显式给名字时，会话名 = 预设 id + 本机到分钟的时间戳（如 `single-20261124-2053`）；没有预设 id 就退到 `work`；子会话是 `<父名>--<角色名>`，不另起时间戳。显式给了名字才用它，重名一律带 `-2` / `-3` 尾号（`src/units/business/runtime/service/action.rs` 的 `derived_session_name` + `unique_work_name`，时间戳来自 `src/kernel/detail/clock.rs` 的 `local_stamp`）。
- `meta.yaml` 的 `agents` 是名单的唯一真相（代拟路径在用户确认那一刻写回）；`sandbox` 段是执行环境的唯一真相（策略 id / 定版 `pins` / 不透明 `params`，缺段按默认读回），`facts` 段是它解出来的事实快照（哪一侧、客机名与系统架构；改声明时同一次重算）。会话级权限层在 `permission.ceiling`（根）/ `permission.narrowing`（子）。
- agent 会话**在第一个讨论回合按需建**（名单确认时不预建），命名 `<工作>--<agent>`。
- agent 会话是**普通会话**：独立上下文、独立转录、独立围栏，复用同一套会话机制；**不新增会话类型**。
- **讨论与执行不分家**：同一个 agent 会话先用于讨论、后用于它的节点，上下文连贯。
- **落盘在主会话目录内部**：`data/session/<工作>/children/<工作>--<名字>/`——位置与 `meta.parent` 同源（看位置就知道归属）；`data/session/` 下不出现与主会话并列的子会话目录，**删主会话就是删一个目录**。
- **可以再往下嵌套**：子会话自己还能有子会话（代理建的协作子工作会派生节点子会话），每一层都是父会话目录下的 `children/<名字>/`；查找、列清单、级联删除都按**任意深度**走整棵 children/ 树。
- **整棵树只有一个共享区根**：不论嵌套多少层，共享区始终是**顶层**那一个（工作根 = 沿 `meta.parent` 走到顶；默认是顶层 `work/`，根会话绑定外部工作区时是 `meta.yaml` 的 `workspace.root`），各 agent 沙箱也建在工作根下；实例名因此在**整棵子树**里唯一（重名自动带尾号，见 registry 的命名策略）。
- **外部工作区绑定**：根会话可在创建时把共享区主副本绑定到产品目录之外的绝对路径；绑定写进 `meta.yaml` 的 `workspace.root`（工作台声明的外部根），整棵子树只读继承，**创建后不可改**。CLI 启动的会话默认就把**启动目录**绑成外部工作区（在哪个目录启动就绑哪个；`ambient` 与 `resolve` 共用一条阶梯但不探可写，启动目录是产品根 / 不可达 / 不是目录时回退产品内 `work/` 并打印原因，`--no-workspace` 关闭这次启动的自动绑定）。`.work/` 与各 agent 沙箱永远留在会话目录内，外部目录里不出现本产品的状态；`.work-root` 只是布局投影，打开 / 重建时按 meta 刷新。
- **虚拟机档的挂载布局**：起 guest 时把**会话树根**（`data/session/<工作名>`，各 agent 私沙与 `.work` 的父目录）与**外部工作区根**（仅外部绑定时）各挂一条稳定挂载，另加模块树根——三根互不包含，guest 内的路径写法由同一座路径桥给出；外部根是 UNC / 网络路径时只有虚拟机档支持（guest 内写成 `/solomni-host/unc/<server>/<share>/…`；本机档因容器围栏拒绝网络工作区）；挂载只表达可见范围，共享区主副本不进按次允许集（容器里的进程要读先 `work_pull`）。
- **环境属于顶层工作**：`sandbox`（策略 id / 定版 / 参数，虚拟机策略的参数里带虚拟根名）由人建主会话时决定，整棵子树只读继承；核心代理建子会话时不能自选环境。**同一 agent 全树只有一份名单**：子会话编辑模块 / 模型时写回这份名单，guest 装配按整棵树重新聚合；只改模型 / 权限不重建 guest，改模块 / 环境才重建。
- 会话权限是**根 ceiling + 子会话逐层 narrowing**：根写 permission.ceiling，子写 permission.narrowing；子只能换更低档、只能收窄，父编辑只改 ceiling 并与子 narrowing 求交，不覆盖子收窄（`src/units/pure/permission/domain/permission.rs`）。共享区归属单独一层：根写 `workspace.params`、子只能更窄（`src/units/business/workspace/domain/scope.rs`）。
- **共享区是版本化工作区**：共享区根（默认 `work/`，或外部工作区）与版本库 `.work/` 都锚在顶层工作上；agent 只写自己的沙箱，`work_pull` 拉取；写工具落地后由核心把整棵沙箱自动记进该 agent 的**存档线**（`refs/agents/<agent>/saves`，不动共享区，只服务回档 / 删除 / 留档 / 恢复）；shell / 模块工具这类不经过写工具的改动，在同一工具批次结束时由核心扫一遍沙箱采纳进同一条存档线（逐条点名没采纳的路径；Windows 本机档容器自己的运行缓存——`AppData/Local/Packages/<容器名>/` 与 `Packages/<容器名>/`，容器名以 `Solomni.Agent.` 开头——不是产物，扫描时跳过，`src/units/business/versions/service/sync.rs`），要发布时先用 `work_commit` 把显式路径记进**工作线**（`refs/agents/<agent>`，本地提交、不判别人的基线），再用 `work_push` 与主线三方合并（干净则主线落一条提交并物化共享区，冲突整次拒绝并点名路径）；`work_versions` 看三方，`work_resolve` 显式选边，`work_status` 看状态。
- 文本、图片、视频与其它二进制都按字节处理（内容流式读写、不整份进上下文；单文件有上限）；`work_versions` 给 hash、大小与扩展名媒体类型提示；文本可人工合并后用 `take=local`，图片 / 视频 / 二进制只能选边，不做自动合并（`src/units/business/versions/service.rs`）。
- **会话权限层**只有网络两档：meta.yaml 的 permission.ceiling（根）与 permission.narrowing（子）只写 profile（offline / online），缺省继承 settings.yaml 的 sandbox.defaults；共享区归属是三态（all / none / 路径数组）+ 黑名单，写在 meta.yaml 的 `workspace.params`（会话只说声明，参数由工作台单元解释），缺省继承 settings.yaml 的 sandbox.scope，sandbox.policy.deny 是硬底线，会话只能追加、不能清空。语义见 [docs/permission/README.md](../permission/README.md) 与 [docs/workspace/README.md](../workspace/README.md)。
- **出站网络是全局开关**（`sandbox.policy.network`）：会话工具、直接模块工具、常驻服务、模块构建共用；虚拟机档决定 guest 网卡；本机档 Windows 授 `internetClient`、macOS 放行 `network-outbound`、Linux `net=false` 用 seccomp 拒绝非本地 socket（`net=true` 不装网络过滤器，不限制入站/绑定）。
- Windows 只放行公网出站，不授 private network / loopback（回环默认全禁；要容器内连宿主端口只能走中继，见 [docs/kernel/README.md](../kernel/README.md)）；Windows 未授权 `windows.write_acl` 时容器不装，网络不生效。
- 侧栏**可见**：agent 会话挂在主会话下（`meta.parent`），用户可进入查看与发言干预。
- 侧栏顺序是**树序**，由核心给出（父会话紧跟它的子会话，深度优先、各自按时间倒序）：顺序与缩进是同一件事的两面，各排各的就会出现"子会话排在父会话上面"的错位。
- 父会话已被删的子会话如实列在最后，不凭空消失。

## 二、回合（轮）

> **一轮 = 所有"还能发言的人"各发言过一次。**

- "还能发言" = 在组 **且** 未同意 **且** 未离开。已同意/已离开的人本轮不问（同意是粘住的）。
- 一次"发言回合"= 核心把讨论上下文交给该 agent 的会话，然后**等**；它可以在自己的会话里调工具（核实）、继续想，**直到用讨论动词表态**。
- **转录永远是核心的活**：子会话从不往主会话写；核心拿到动词才转录主会话并往下走。

### 计数与提醒（讨论阶段）

- **模型调用次数没有上限**：子会话继续核实就继续跑，直到模型不再发起调用、或用户点「停止」。
- 不上"到顶直接收尾"这类天花板——它会把"还想接着核实"误判成"必须收尾"，执行席因此干到一半被掐断（`src/units/business/agentloop/engine/round.rs`）。

- 留下的只有**提醒次数**：这一轮对它提醒过几次（默认 3，可设置）。

- **什么时候提醒**：这一回合结束在**纯正文**（没有用讨论动词表态）时，核心**只注入一条提醒**（"你还没用讨论动词表态"，见下"系统消息"）——**不强制**它表态。
- 提醒次数**到顶**：本轮放它过去——主会话如实记一行 **"未回应"**，整轮继续（**不阻塞**）。
- **何时归零**：每轮开始、进入下一阶段，或它给出了讨论动词/回报时。
- **用户主动中止**时不提醒（用户可能正想和它讨论）。用户和它聊完、点上下文「继续」后，它**仍要给出讨论动词**才算发过言。
- 收敛、上限、退出、请教（ask）的判定与 task-chain 一致，只是"问谁"变成"问它的会话"。

### 系统消息

- 系统注入的东西（提醒、压缩边界、工具围栏降级这类**不是用户说的、也不是模型说的**内容）必须有**系统消息**这一种转录行（`src/units/business/transcript/domain/events.rs`），不能在转录与前端里长得像"用户发的"。

- 结构化信号随行落档（`system: true`），呈现层据此换样式，**不靠匹配文本**；进上下文时按它该有的角色进去（提醒是给模型的指令），但**用户看到的是系统行**。

- **内容类系统提示是另一种行：`kind: "notice"`。** 它只给人看、**不进模型上下文**，有会话内稳定 id，能与普通行一样折叠、回档、删除（建组、阶段验收、返工、停止、中断、代理授予/转达…）。
- 分配点在会话对象里（`AgentSession::note_notice` / `CollabSession::notice`）——和普通行共用一个单调计数器，落盘、重建、回档因此走同一套账；重建时 `replay_dialogue` 明确跳过它，不产生任何消息。
- **协作的裁决事实也走这一种行**（`LineView::record` + `CollabSession::record`）：核心整理的方案、总验收清单、交付结论都落成带 id 的 `notice` 行，身份放在 `speaker`（核心整理 / 验收清单 / 交付）——刷新、回档、换端都读得到同一行。对应的 `Push` 事件（`plan` / `review` / `delivery`）只作流程视图的增量，**不再由前端自造转录行**（否则同一件事两处画、刷新即丢）。

- **不是所有提示都行化**：过程性提示（工具调用形态变更、"末条是 AI 发言"这类提醒）、工具层确认（放行前的「待确认」、放行后的「确认」）与基础设施故障（落盘失败、线程崩溃、无回应）保留为**瞬时 `Notice` 事件**：它们的持久事实是裁决卡 / 回答或 meta，不是转录内容。
- 工具层也拿不到会话的行计数器。它们照样推给在场的前端，只是没有 id、不可回档、**不写 `transcript.jsonl`**：原始 `Notice` 是瞬时事件，刷新后不该再出现；「停止 / 继续」这类控制动作即使发生在生成期间，也只保留瞬时提示，真正的持久事实是 `meta.run` 与生成收尾的 `[停止]` 内容行。

- **派发行**是系统行里的一种（`system: true` + `task: true`）：核心给某个 agent 派的活。

- 界面上它和别的系统行一样是核心说的话——**不得显示成"用户"**（`src/units/business/transcript/domain/events.rs`）；上下文里它以 **user 角色**转发：派活是一次**回合**，而会话协议要求请求里至少有一条 user 消息，一条 user 都没有的请求会被供应商**整条拒收**（全 system 的请求返回 400）。
- 讨论席同理——它每次都用一条 user 回合（opener / step）开场。
- 两处口径都随行落档，所以**重建/回放产出发出去的那同一条消息**（见 [六](#六节点执行只有一条管道)）。

### 会话种类 × 推 / 落

- **推是一处、无条件的**（底层收发该做的事）；**留不留由会话种类定**（不由调用点定）：

| 会话种类 | 推 | 落（判定只有一处：`persist_policy_for`） |
| --- | --- | --- |
| 单 agent 会话 | 定稿行 + 短暂事件 | **留**：逐轮的正文/工具/思维链——那是模型上下文的一部分，不留则重启后上下文歪 |
| 协作会话（含**核心自己的操作**） | 同上 | **留**：协议行 + 发言投影 + 核心的工具行/思维链/正文 + 派发/完成/阶段/返工通知——它是派生状态的来源，用户也要对账 |
| **系统会话**（sid 以 `#` 开头） | 同上 | **不留**：一次性动作（让核心推荐 agent、探针、一次性判定），重启后本来就该是空的；它**不进会话表**（`/api/state` 里没有它），所以前端不会为它建标签页 |

- 短暂事件（`Delta` 增量 / `Working` 运行态 / `ToolCall` 实时工具卡）**任何会话都不落**——它们只给在场的前端看；`/api/state` 与推来的事件已经把"当前该显示什么"说清。

- **上下文用量是独立事件**：`usage` 记录最近一次模型调用的 prompt / completion / total、当时的窗口与"精确还是估算"。
- 它**不落成转录行、不进模型上下文**，随会话流水落盘（刷新/重建可恢复）；`line` 是这次调用产出第一行的行号，回档折叠到它之前时这条用量随之失效。`SessionView.context` 是同一份事实的快照，**只给有持续对话的 `Session::Single`**（single / proxy / 协作的 agent 子会话）；协作主会话是流程会话（`Session::Flow`），没有这个字段。
- **累计花费是 meta 事实**：`SessionMeta.usage_totals`（calls / prompt / completion / cache_read / cache_creation）跨回合、跨压缩累加供应商**精确报回**的用量——每次模型调用都记，压缩调用也记；字符估算不进账，回档不清零（花出去的钱退不回来）。`SessionView.usage_totals` 是同一份事实的快照，面板的「累计输入 / 输出」与「缓存（累计）读 · 命中率」读它；「已用 / 占用」仍跟随当前发送视图。
- **shell 状态也是快照**：`SessionView.shell` 取该会话最近一次 shell 的运行槽（命令、cwd（本环境写法：本机档是宿主路径，虚拟机档是 guest 内路径）、起止、耗时、退出码、状态 `status` 与回执预览；`status` 取 `exit` / `timeout` / `stopped` / `signal`，None = 运行中 / 未执行 / 没跑成），由工具循环写、状态栏读；它只服务界面，不进模型上下文，也不替代转录里的 shell 工具行。**重建 / 回放按转录派生**：`last_shell` 从内容日志 `Content`（`folded_away` 的活动视图）取最后一条带命令、带结构化事实的 shell 工具行（`tool.shell`：cwd / 耗时毫秒 / 围栏准备 / 退出码 / 状态 / 是否截断），不解析回执正文——标 `historical`、不伪造起止时间；回档折叠掉的行不参与派生。`/api/history` 在响应里带同一份快照，前端本地没有时才填。首次按会话授权的外部工作区，其围栏授权等待计入这条回执的总耗时（粒度见「外部工作区绑定」的 `workspace.grant`）。
- **裁决卡与回答是例外**：`DecisionCard` / `DecisionAnswer` 按上表落盘（单 agent 与协作会话都留、系统会话不留）——"用户答过什么"是会话的事实，重启后卡与答案都要在（见"请用户裁决"一节）。

- **会话表由后端给，前端不自己造会话**：前端只为 `/api/state` 会话表里"后端说在跑"的会话建标签页，事件流里出现**不认识的 sid** 一律不动（只置位，等下一次状态刷新把会话表带进来）（`src/presentation/web/assets/app/features/transcript/events.js`）。
- 理由：为事件里冒出来的 sid 就地建会话＝前端自己造会话状态；系统会话不是真会话，它会因此冒出一个多余的标签页，而真会话的记录又会被建重一遍。
- 于是系统会话推出来的行**没有任何前端动作**：它不在会话表里、也不落盘，就是底层那一次无条件的推。

- **历史与实时合流，前端不合并两个来源**：`GET /api/history/{name}` 一次给全盘上转录 + 事件台上它之外的尾巴，并给出合流时的头部序号当**水位**；此后 `seq ≤ 水位` 的批次丢掉、之上的按序 append（见 [contracts.md](../presentation/contracts.md)）。
- 判据是结构化相等而不是行 id——`node_started`/`report` 与瞬时提示没有行 id（内容类系统提示已经是 `transcript` 里的 `notice` 行，有 id）。
- **节点进度不落转录行**：`plan_review` / `node_started` / `report` / `review` / `delivery` 只是事件台里的进程事实，界面把它们画成状态栏上方的流程视图（展开后列出整条链，按状态着色），转录里没有「节点」这一种行；刷新与回放靠同一批事件重建（`src/presentation/web/assets/app/features/flow/flow.js`）。
- **回档会推进重置水印**：水印之前的批次已被盘上转录取代，`live` 只取水印之后；前端收到 `rewound` 时清空重建。

- **行身份是结构化字段**：一行带 `speaker`（谁说的）/ `verb`（动词：say / agree / 需求 / 开始…）/ `kind`（`msg` 模型发言 / `user` 用户说的 / `system` 系统注入或核心自己的行 / `notice` 内容类系统提示 / `tool` 工具行 / `round` 轮次分隔行），**正文里不带 `[谁:动词]` 标签**。`LineView::render()` 是"字段 → 文本"的**唯一**拼法：提示词里的转录（`{{transcript}}`）与回放比较都读它；呈现层按 `kind` 换样式、按 `speaker`/`verb` 显示身份，不解析文本（见 [contracts.md](../presentation/contracts.md) 的推的事实）。

- **助手原文是回复级事实**：`LineView.raw` 每条回复只落**一份**，挂在该回复首行（有正文时是正文行，纯工具轮是首条工具行）；信封模式下含信封 JSON，原生模式下即可见正文。工具行只记参数（`args`）、正文（`output`）、轻重（`severity`）与说明（`notes`：稳定码 + 类型化参数），不再各带一份原文。**说明在边缘渲染**：模型通道按源语言把 `notes` 逐行接在正文后（`[工具结果] <名字>` + 正文 + 说明），界面按当前语言的词表渲染同一组码——存储只留码与参数，换语言不改转录。重建与实时都从这一份还原 assistant 消息，呈现层只在整轮气泡显示一次。

## 三、谁驱动谁（实现形态）

> 契约要定死这一点，否则会出现两套"谁驱动谁"的说法。

- **讨论不由泵自己调模型，而是"泵只决定、核心驱动"**——与任务链的节点派发**同一套路**。

- 理由是会话归属：生成期间协作会话被**移出核心表**（own-and-return），它碰不到表里的 agent 会话；而 agent 会话必须留在表里，用户才能随时进去发言。所以**驱动权归核心**（它同时看得到两边）（`src/units/business/turn/turn/service/flow.rs`）。

- **驱动只认流程面**：核心驱动（`src/units/business/turn/turn/service/flow.rs` 与 `src/units/business/turn/turn/service/generation/collab.rs`）与具体流程之间只隔一层 `session::api::Flow`——开场 / 推进一步（`start` / `step`）、取走让出的一步（`take_ask` 交出 `MemberAsk`）、交回处置（`handback` 判为 `Handback`，再由 `feed` / `pass_over` 落地）、处置自己发的关卡（`settle` 把出队的票交回流程，`settles_inline` 决定这一关要不要就地收尾）。可派的活（`WorkPlan`：哪些节点该派、谁在跑、节点的提示词与返工提示、开跑与收工的记账、开工事件）也走这层面，节点派发与改需求不再下行认具体流程；其余通用动作（撤回同意、改需求的沙箱改写、行号、子会话的默认作答）同样是流程面的默认方法。协作的实现只有 `src/units/business/collab/service/flow.rs` 一处；换一套流程只换一个实现，驱动不动。
- **流程可以串起来**：会话类型表里的 `flows` 是一串，装配期用 `turn_state::api::sequence_of`（`src/units/business/turn_state/domain/sequence.rs` 的 `Sequence`）串成一条——前一段 `is_done` 就把自己的 `output` 交给下一段的 `intake`（行号一路传下去），驱动仍只认一条 `Flow`。交接的东西不是裸字符串，而是 `session_model` 的 `Artifact`（`src/units/business/session_model/domain/artifact.rs`：`Requirement` 用户需求 / `Summary` 上一段的文本产物）；复合流程只搬运、不看内容，接不接得住由段声明 `Loop::accepts` / `produces`（`src/units/business/session_model/domain/mechanism.rs`）在装配期校验——第一段必须收得下用户需求，后一段必须收得下前一段交出的产物，声明错了 `Profiles::validate` 当场报错。业务面（`part` / `part_mut`）指向**当前这一段**，所以派节点、改需求这类动作不必知道自己是第几段。会话级事实由驱动同时通知每一段（`adopt_roster`：代拟的名单一确认，后面那一段也要认得出谁能出演）。协作就是这样拆成两段的：`discuss` 交出的总结成为 `execute` 的需求。
- **装配按类型表点菜**：新建与重建都只问类型表要 `flows` 的 id，经组合根注入的流程工厂（`turn_state::api::Flows` + `FlowSetup`，`src/units/business/turn_state/domain/flows.rs`）逐段造出来再串起来；`work` 与 `turn` 因此不出现任何具体流程的类型（`src/units/business/work/service/create.rs`、`src/units/business/turn/turn/service/rebuild.rs`）。
- **关卡归发起它的流程**：队列只认卡、卡号与选项（`kernel::Ask`），不解释 `kind` 是哪一关；回答出队后驱动把 `GateTicket` 交回流程面的 `settle`，由流程自己落定并说要不要接着推进（`Settle`）。所以 `runtime` 与 `turn` 里不再有「这是代拟名单那一关」这类判断。

### 看不见的回合：运行态与逐片外送

- 成员回合跑在**它自己的会话**里，主会话在整回合里一个事件都收不到。所以核心要主动交代两件事，否则用户看到的界面就是"整回合不动、只有手动刷新才同步"：

- **逐片外送**：成员回合与**核心操作**的正文都逐片推 `Delta`（沿用"到 `{` 就截住"的分片规则——信封绝不当正文流出），核实行实时推 `ToolCall`。外送目标是**该 agent 自己的会话**（打开它的标签页就能看到它逐字在说、在读文件）。**被截住或合并掉的空片段不推事件**（`session::api::delta_visible`：只有 `start` 与有内容的片段外送），否则长信封会让前端每秒收到几十条空 delta、看起来像卡死。
- **逐轮定稿**：成员回合与单 agent / 节点回合跑的是**同一条轮循环**（`engine::converse_with`；这一回合的参数收在 `session::TurnRun`：身份、角色、本回合提示、表态约定、回合号）。
- 一轮跑完就出这一轮的行（`engine::build_round_lines` 是**唯一的行构造点**），那批行**同时入它自己的事件台与落盘**——只落盘的话，那个标签页的流式块永远等不到替换它的那一行，正文一直挂着闪烁光标、看着像"还在流式"。思维链随该轮的权威行保存（工具轮没有正文时挂到工具行上），流式结束或重放后仍可查看；没有定稿的停止/错误分片在空闲事件到达时撤下，不冒充转录。
- 主会话那份是**投影**（`feed_with` 只投影"谁说了什么"），与子会话各一份、互不重复。
- **运行态的唯一真相是事件**：`SessionEvent::Working { agent }`（短暂、不落盘，`None` = 空闲）在"要问谁 / 这条会话开始生成"时推带名字的那条、收尾推空闲；**主会话与子会话各推各的**——子会话若只靠"有增量=在跑"推断，收尾就永远清不掉：那个标签页一直显示"正在工作"、按钮一直停在「停止」。
- **`/api/state` 的 `running` 是对账副本**：前端只在"本页对这条会话还没有实时知识"时用它（刚刷新页面、事件台裁掉一段后的重连、别人建的会话）；收到过 `Working` 之后只认事件——一次迟到的轮询不会把已经收尾的回合标回"在跑"；事件台出现补不齐的缺口时实时知识作废、退回对账。
- 前端的按钮切换（发送/上下文继续 ↔ 停止）、占位动画（"正在工作：某某"）都读这条运行态；此外"本页发出的命令还在途"也算忙——那是本地事实（防重复提交），与服务端运行态不是一回事。

### 落盘的运行态：停止 / 归档

- "这一刻在不在跑"是短暂事件（`Working`）；**"这段工作还该不该继续被驱动"是持久事实**，落在 `meta.yaml` 的 `run` 段（`active` / `stopped` / `archived`，缺省 `active`）：

- **`stopped`**：已停止（**历史态**）。此后的**派发与唤醒一律被拒**（"取会话去生成"那道闸 `Core::dispatch_gate` 两者都拦）；正在跑的那次会被**级联停掉**。界面按历史态渲染它：输入区收起，只留「启用会话」——启用是显式的恢复动作，只恢复会话（含虚拟机 guest），**不产生模型调用**。停着的时候**不给「继续」**：派发会被拒，那个按钮只会是假入口。
- 真正"接着走"由上下文继续负责（见下），它只在会话**活跃**且有真实断点时出现：单 agent 上一轮被打断时给「继续」，协作泵没走完时给「恢复协作」；没有断点、正在跑、代理、`stopped` 与 `archived` 都不显示（`Work::continue_action`，`src/units/business/work/service/views.rs`）。
- **`archived`**：已归档。从会话列表收起，**派发与唤醒一律被拒**；归档那一下整棵子树里还有在生成的就先**中断**再归档，不留半个状态。它不是终态：「恢复归档」把整棵子树翻回 `active`，**不唤醒、不产生模型调用**；彻底收尾只有删除（拒绝在 `SessionMeta::dispatch_refusal`，`src/units/business/session_model/domain/history.rs`；归档 / 恢复走 `control_session` 的 `archive` / `restore`，`src/units/business/runtime/service/bridge.rs`）。
- 判据只有一处（`SessionMeta::dispatch_refusal`）：转达、观察、控制与叫醒都问它，不各写一份。
- 重启 / 回档后照样成立（它就是 meta 的一部分，不属于"这一刻"的短暂态）。
- **启用 / 继续分开**：历史回放只读，已停止的活动视图同样收起输入区，这两种状态都只有「启用会话」；它由 `activate_session` 走两段式（核心准备 → 调用方线程起 guest → 核心提交），不跑模型、不写转录。启用后 `SessionView.continue` 才决定是否显示上下文继续；前端不自己判断末条或协作泵。
- **「继续」不替用户发言**：末条已是用户发言，就直接拿现有对话问模型——`TurnOps::continue_flow` 调 `single_generation(sid, None)`（`src/units/business/runtime/service/contracts.rs`），转录里**不会多出一句"用户：继续"**；要新增用户发言的只有 `say`。末条是 AI 发言时只提醒「请先发言再继续」，不发请求（`Turn::prepare_single`，`src/units/business/turn/turn/service/turn.rs`）。
- 「继续」在服务端**同步跑完整轮**才回包（`TurnOps::continue_flow`，`src/units/business/turn/turn/api.rs`）：回包要等回答结束。界面因此不能等回包再启用视图；已停止 / 已归档的恢复不走它（走 `activate_session` / `restore`）。
- **中断 ≠ 停止**：界面上的「中断」只取消在跑的生成、作废等裁决的队，**运行态保持 `active`**（会话照常可派发、可唤醒）；「停止会话」才把整棵子树落成 `stopped`。
- 用户点「停止」= 先把整棵子树落成 `stopped`、再中断正在跑的生成（**顺序不能反**：反了的话，被停会话收尾写的那条"这一轮结束"会先把父会话叫醒）。
- **停止要取消在途请求，不是只置一个标志**：LLM 出站适配器在等待响应/下一个数据块时轮询取消位，置位即关闭连接；生成循环在解析载荷、执行任何工具**之前**再检查一次取消。已流到一半的 tool_call 不执行；已经写出来的正文留在转录里并标「（已中断）」，但不进模型上下文（不算这一轮的回答）。
- **模型调用超时分三层**：连接 10 秒；首响应/首个数据块用设置里的预算（`llm_timeout_secs`）；流已经出数据后，两个数据块之间最多等 120 秒，收到任意字节（含 SSE keepalive）即重置。
- 正常流式没有总时长上限——只有真正等不到下一个字节时才中断；非流式调用仍把这份预算当整次调用的上限。
- **调用失败不是模型的回复**：`Completion.error` 与正文分离，上层据此发 `Notice` 并**中断本轮**（不落转录行），会话保持可继续。出站调用的参数由核心决定、随端口传下去（`LlmOpts{stream, timeout_secs}`），取值来自**全局设置**；`Output` 只管回包形状。

### 请用户裁决：一个形状，一条队，两种时序

- **任何需要用户裁决的 yes/no 都走同一条通道**：核心请用户定的事（名单确认 / 开始讨论 / 请教 / 方案待审 / 节点没过）与工具层自己发起的一类（例如围栏这一环装不上）。
- 形状只有一种：`kernel::Ask`（`src/kernel/contracts/types.rs`）——`role` / `name`（谁在问）、`title` / `body` / `detail`（问什么）、`options`（有序的 `{id, label}`）、`kind` 与 `payload`（哪一类关、机制自己解释的材料）、`notes`（稳定码 + 类型化参数）。发起方填形状，通道不解释内容。
- 后端只有一份队列实现（`Gates`，`src/units/business/turn_state/domain/decisions.rs`），前端只有一种渲染。

> **接入范围**：核心的每一关与工具层的提问（`kernel::ports::AskUser`）都走同一条队：卡、回答与作废都落盘，重启按转录整队重建；
> 同一会话一次只问一条——并发发起时后到的排队，界面与快照都带着「谁在等、前面还排着几条」；
> 用户按停止（或归档会话）时整队作废，等待方按「停止 = 拒绝」解开；
> 回答与「停止」同一条直路——回答先落定（校验 + 出队 + 记一条回答），处置再脱离调用方跑。

- **谁发起就归谁收场**：队列只认卡、卡号与选项，不解释 `kind` 是哪一关（`src/units/business/transcript/domain/events.rs` 的 `card_of` / `waiter_of` 只把 `Ask` 翻译成卡与「谁在等」）。回答出队后驱动把 `GateTicket { option, note, ask }` 交回流程面的 `settle`，由流程自己落定并说要不要接着推进（`Settle`）。
- **两种时序，判据是「等待方还在不在」**：
  - `later`：不阻塞，发起方记下卡号就继续干自己的事（协作泵的关卡全是这一类）。流程重建时它还在，所以能按转录重挂，并**沿用原来的卡号**（`AskDesk::later(Some(id), …)`）。
  - `wait`：阻塞等一个选项（工具层与围栏走 `kernel::ports::AskUser::ask`）。等待方是活线程，重启后它已经不在了，所以这一类**不重建**——不是靠 kind 白名单，而是线程不在就没有等待方。
  - 两者共用一条队、一份落盘格式，只是结束方式不同。
- **没有默认项**：`AskOutcome` 只有 `Chosen` / `NoAnswer` / `Stopped` / `NoOptions`，`Ask` 上不带「没人答就当选了什么」。没人答就是没放行，由发起方按 fail-closed 收场（围栏因此拒绝这次调用）。理由：默认项等于让通道替用户做决定，「停止 = 拒绝」这条判据会被它悄悄破坏。
- **空选项集不自停会话**：端口回 `NoOptions` 并留一条 `Notice`，停不停由发起方决定——通道无权替会话判生死。
- **必须阻塞**（`src/units/business/turn_state/domain/ask.rs`）：`wait` **不设超时**——不点不继续；终止只有三件：用户回答 / 用户按停止（解成**拒绝**，不是放行）/ 会话被删除；停会话时整队作废，等待方一律按「停止 = 拒绝」解开。
- **队列**：同一会话同时只问一条——多席并发按先来后到排队，**只有队首那张可见、可答**（排在后面的答了会被「卡号不是队首」挡下）。界面与快照都让「谁在等、前面还排着几条」可见：推的卡片事件与 `/api/state` 的 `pending` 都带 `waiting`（队首之后还在等的那几张，每条带自己的卡号与这一关的重建材料）。
- **回答只有一条命令**（动作 `answer_card`，带上卡片 id + 选项 id（可带附言））；回答要**校验选项 id 属于当时那张卡的选项集**（防旧卡的答案被用来放行新的请求）。
- **落盘**：卡片（`DecisionCard`）、回答（`DecisionAnswer`：谁答的、选了哪个 id、附言）与**整队作废**（`DecisionVoid`：作废了哪几张、为什么）都按上表落盘。`/api/state` 的 `pending` 是同一份事实的快照形态（重启后由转录重建）。
- **已答过的不得重问**；作废过的也不复活（那一关还挂在状态上时，`继续` 才**续一张新卡**接着问）（`src/units/business/turn_state/domain/ask.rs`）。
- **选项行为靠稳定 id 映射**：文案可改、可本地化，id 是契约（回答按 id 分派，改文案不改行为）。
- **没有「不可选」的选项**：**禁止置灰**（`src/presentation/web/assets/app/features/transcript/cards.js` 的 `renderCard`）——置灰会让会话卡在那里没人点得到东西。卡片一旦推出，选项集**不可变**：要改只能作废这一条（界面如实标「已作废」）再推新的，绝不静默改写用户已经看到的选项。
- **代理转达不替用户猜**：`send_session_message` 要代答就**显式给选项 id**（`reply`）；给不出就不作代答、如实记一条，那一步按发起方自己的收场办——绝不「取第一个选项」（围栏卡的第一项正是「无围栏跑一次」）。
- **不做跨会话的「记住这个决定」**：只保留「本轮不再问」（不落盘）。要「记住」另立设置项——否则裁决对象会变成策略载体，与 `units/pure/permission/` 那套裁定重叠。
- **建议由核心写**（随产生这一关的 `plan` / `node_verdict` 调用一起产出，不另花调用），它是消息的一部分。

- **回答怎么落进业务**（处理仍归发起方）：

  - **请教**：用户的话进**主会话转录**（所有成员下一回合都看得到），不单独转给发问的成员；
  - **方案待审 / 节点没过**：由**核心判定意图是否明确**——明确才开工 / 放行，模糊就不开（他的话进主会话当反馈，关卡继续等着，核心不自动往下推）；
  - **围栏这类底层**：按选项做它自己的事（「本轮无围栏跑一次」）；没人答 = 这次调用**没有执行**。
  - **改需求不是裁决**：它是会话级动作（会话视图的能力位 `can_update_task`），用户自己点；没有「本次需求」的会话**根本不渲染**这个按钮，会话工作中不可点。

- **关卡归发起方机制**：会话只装 `Ask` 的 `kind`、`payload` 与卡；下表是协作的关卡。

| 关卡 | 选项 id |
| --- | --- |
| 请教 | `ask_reply` |
| 代拟名单 | `slate_confirm` / `slate_cancel` |
| 开始讨论 | `begin` / `begin_allow` |
| 方案待审 | `plan_start` / `plan_say`（先说一句，由核心判定明确性） |
| 节点没过 | `node_rework` / `node_say`（同上） |

- 工具层那一问（围栏装不上）自带 `kind = fence` 与 `payload`，选项是 `fence_unfenced_once` / `fence_abort`（见 [docs/kernel/README.md](../kernel/README.md)）。
- **策略提出的那一问**：流程段可以在 `Loop.ask` 里声明「这一段里哪些动作要用户点头」，引擎把这一次调用翻成一张 `kind = policy` 的卡（`src/units/business/agentloop/domain/policy.rs` 的 `ask_card`：`name` 是 agent，`body` 是策略给的理由，`detail` 写明段与角色，选项固定 `allow` / `deny`），走同一条队、同一套落盘。**只有答了 `allow` 才执行**；`deny`、没人答、被停止、构不出选项，以及这一趟没有可回答的前端，一律当没放行——回执写明这一次没有执行（`src/units/business/agentloop/engine/tools.rs` 的 `gate`）。

### 泵的状态机

- 泵按步推进，可暂停、可恢复：

```text
泵的每一步只做三件事之一：
  AskMember { agent, msgs }   该问谁、给它什么上下文（本回合的讨论上下文）
  Notice/事件                  如实外送（轮次边界、越权、沉默…）
  Done / AskUser / Interrupted 终态
```

### 一步的完整序列

```text
1. 核心：take_collab(sid)                   协作会话移出表（own-and-return，不破不变量）
2. 核心：泵推一步 → AskMember { agent, msgs }
3. 核心：put_collab(sid)                    先放回，腾出手
4. 核心：take_single(<工作>--<agent>)       该 agent 的会话移出表
5. 核心：跑这一回合（TurnRun：动词 + 角色）  与单 agent 同一条轮循环，见"逐轮定稿"
6. 核心：put_single(...)                    放回（转录增量落盘在它自己目录里）
7. 核心：投影 → 主会话追加"该 agent 的发言行"（带 turn 标记）
8. 核心：回到 1，直到泵给终态
```

- **回合标记**：第 5 步在该 agent 的会话里写一行 `[回合 tN｜第 M 轮]`（**系统行 + 系统消息**：不是谁说的，回档按同一口径还原）；第 7 步投影出来的主会话行带 `turn: tN`——两边同一个 id（回档同步靠它，见「回档：三种模式 + 工作级标记」）。
- **核实行**（只读工具的调用）落在**该 agent 的会话**里：与单 agent 的工具行同一形态，由同一条轮循环逐轮产出。
- **用户进 agent 会话说的话**：下一回合它自己就带着（就是同一个会话），不需要额外同步。

### 不变量

- 任何时刻**只有一个**持有者：要么核心表里、要么在跑的那一步手里（与 own-and-return 一致）；
- 主会话状态的改写**只有核心**做（泵只产出"该说什么"）；
- 一轮的边界不变：**所有"还能发言的人"各发言过一次**（见二）。

## 四、发言投影与标记

- 成员的**发言发生在它自己的会话里**（它调用讨论动词），由**核心投影到主会话**——主会话状态的改写只有核心做。

- 两边用**同一个回合 id** 对上：

| 落在哪 | 记什么 |
| --- | --- |
| agent 会话 | 该回合开头一行标记：`[回合 t17｜第 2 轮]`；其后是这一回合的工具调用与最终发言 |
| 主会话 | 投影出来的发言行带 `turn: t17` |

- 于是"这条发言对应它在自己会话里做的那些事"是**可跳转的事实**，回档也有确定算法（见「回档：三种模式 + 工作级标记」）。

- 讨论阶段产生的行（核实行、回合标记、发言）只落进该 agent 自己的会话与投影行，不写共享区。

### 转录即状态与行的结构

- **转录就是会话状态**：会话内容 = 按 `rewind` 标记回放出的**活动窗口**；内存与落盘不一致时**以流水为准**。留档只追加一条 `{"type":"rewind",mode:"archive"}` 记录并折叠活动窗口（字节全留、可恢复）；删除与恢复**整体重写** `transcript.jsonl`（真的删）。三种模式的机制见「回档：三种模式 + 工作级标记」。
- **行 id 稳定**：一轮模型调用 = 一条行，工具调用自成一条行；id 在会话内单调、回放可复现（回档按 id 定位，被折叠的 id 永不复用）。
- 行上带 `reply`（= 该回复第一行的 id）：重建时按它把同一次回复的工具行归成一组，回档按它**原子**截断。
- **流式增量是短暂事件**：`delta` / `tool_call` 不落盘，历史只记定稿后的行；行上的判定走结构化字段（如降级的 `degraded: true`），呈现层不匹配行文本。
- **工具调用形态**（`ToolMode`：`envelope` 手写信封 / `native` 原生调用）是**登记处的事实**（`models.yaml` 的 `tools`），**不钉在会话里**：每次生成前重新解析，变了就就地刷新系统提示并给用户一句通知；**两套形态互斥**。
- 一次回复在上下文里是「一条助手消息 + N 条结果」，两种形状由唯一的构造函数 `session::api::reply_msgs` 按当前形态产出——"重建与实时逐条一致"因此是结构保证。
- **工具声明里的 `parallel` 决定并发**（缺省 false = 独占）：一次回复里**连续**的可并发调用合成一批并发跑，其余各自独占；工具行、结果消息与账本合并**一律按原始调用顺序**——并发只影响执行，不影响上下文里的顺序（`src/units/business/agentloop/domain/session.rs`）。
- **观察账本**（`systool::Observations`）是**进程内状态，不落盘**：记"本次会话读过 / 由核心写过哪些文件、当时的内容指纹与覆盖行区间"，并随工具行进 `ToolCallView.observations`；每条事实带格式版本（`OBSERVATION_FORMAT`）与来源，格式不符或损坏的事实降级为"没有观察"。它是**先读后改门禁**的依据：受管文件（主线或该 agent 工作线里的路径）整份覆盖要求当前上下文里有这一版的全文覆盖，单处 `edit` 要求有这一版，`replace_all` 要求全文，`patch` 的 Add 覆盖同 `write`、Update 只要这一版。
- **只认产生调用之前已发出的行**：同批并行调用互不授权；压缩按 `up_to` 丢弃事实；回档清空；按落盘重建的会话从转录里压缩点之后的观察事实重建账本。读台账（过期占位符的输入）与观察账本**同水位**：同一个 `reply` 过滤、同样随压缩丢弃、随回档清空，由同一次转录扫描一起重建。
- **覆盖面按行记**：完整读 = `Full`；`offset` / `limit` 截过的读 = 看到的那段行区间（机制层按行窗口流式扫完整份，超过 1MB 也能直接读后半段，行区间按绝对行号记）；单行被显示上限截断、`lossy`、越界空读都不记；成功 `write` / `patch Add` 记 `Full`，成功 `edit` / `patch Update` 只记改动行（相邻/重叠区间合并成一段）。同一版本的多次分段读按并集授权：合起来覆盖 `1..=total` 就等价于完整读。版本是整份内容的 SHA-256（不是截断前缀），当前版本变了就是过期，必须重读（`src/units/business/tools/api.rs` 的 `ObservationFact`；判定见 `src/tests/tools/gate.rs` 与 `src/tests/workspace/work.rs`）。
- **检查与落盘在同一把锁里**：门禁只决定"需要哪种证据"，真正写盘时 `SysIo::mutate` 在按路径的跨进程文件锁里重读当前内容、再比一次版本（`Expect::Version` / `Expect::Absent`），对不上就整份拒绝并返回 `FS_STALE_VERSION` / `FS_ALREADY_EXISTS`，不会把检查之后的别人改动覆盖回去；锁目录由组合根注入（`home/locks`），测试替身可用进程内锁。拒绝时按路径记一条 `warn` 审计（错误码、需求、观察/当前版本，不含文件正文）；一批补丁只取一次工作区快照。写盘走同目录临时文件 + 原子替换；`patch` 的多文件改动走 `transact`，先全部校验/暂存再发布，任一文件失败就回滚已发布的文件（`src/units/business/tools/detail/sys_io.rs`）。
- **受管边界**：只有 tracked 路径受门禁（主线 head 树 ∪ 该 agent 工作线 head 树）；新建与未受管文件不要求先读。不透明写者（shell / 模块工具）写后只进存档线、批末采纳，账本不自动更新，它们改过的受管路径因此会过期；未读改动在 `work_commit` 发布口被硬拒。
- 会话的旁路配置记录（`{"type":"config"}`）只在编辑提交时追加：供呈现与审计，**不进模型上下文**，回放与状态派生跳过它。
- 执行计划本身**从不落盘**（含真实路径，只在运行时派生）；网络与围栏要求是全局策略，不在会话里。

## 五、工具面按回合给

- 同一个 agent 会话，**按回合**给不同的工具面：

| 回合 | 工具面 | 为什么 |
| --- | --- | --- |
| 讨论回合 | `read` / `grep` / `list` / `shell` + 讨论动词（say/agree/leave/ask） | 讨论只做**核实**（资料齐不齐、脚本在不在、README 怎么说）与分工；**不产出成品** |
| 执行回合 | 全工具面（文件域 + 该 agent 的模块工具） | 干活发生在执行回合，产物可追溯到节点、可验收 |

- **模块工具只在执行回合给**：讨论回合的会话类型（`collab` 的子会话）不挂 `module` 来源，所以拿不到"干活"的手段——不是"被拒绝"，是**没有**。
- **这一份工具面是随回合注入的**：核心查"这一回合的身份能用的工具"。信封通道把那一份（说明 + 参数）作为一条系统消息放进该回合的上下文；原生通道由**声明槽**下发名字 / 说明 / JSON Schema，不再重复文字清单（只保留 patch 这类声明表达不了的写法）。**整本工具总表不进提示词**——列了必然被拒的工具等于请模型去撞墙（细则见 [tools-and-roles.md](../tools/tools-and-roles.md) 二）。
- 工具来源（src/units/business/session_model/domain/tools.rs 的 `ToolSource`）**各自交 id**：agent 按能力组交文件面与执行面、module 交限定 id、loop 交当前这一回合（段 + 角色）的机制动作、workspace 交 `work_*`、profile 交会话类型声明的系统工具；这一面由**唯一装配机**现拼（src/units/business/agentloop/domain/assemble.rs 的 `assemble` → `FaceInput` / `SeatFace`，实现见 `sources.rs`）：发放（提示词块与原生声明槽）与越权校验同出一份清单，代码里不另写名单。回合只携带**段与角色**（`TurnRun.loop_id` / `TurnRun.role`）：每回合驱动换身份时由会话现拼这一身份的面并还原（AgentSession::enter_identity → MemberTools::enter_identity）；节点 / 单 agent 回合在准备段就把身份装进会话，不沿用会话出生时的面（见 [tools-and-roles.md](../tools/tools-and-roles.md) 三）。
- **派发三类来源同一条路径**：这一回合的工具面里，系统工具走 `ToolExec::run_builtin`，模块工具走 `dispatch_external`，**核心自有工具**（代理工具等）问注入的 `ToolHandler` 谁认领它——三类同一条路径（`src/kernel/ports.rs` 的 `ToolHandler`，见 [architecture/README.md](../architecture/README.md) §二）。加一类工具只注册一个 handler，不改循环。

### 四之一、会话参数与对话分开

- 一个 agent 会话里有两类东西，**不放同一个地方**：

| | 是什么 | 放哪 | 何时进请求 |
| --- | --- | --- | --- |
| **会话参数** | 身份（agent 名 + 模块能力包）、工作环境（本环境写法的根目录）、调用约定 | `SessionParams`（结构化字段） | **每次调用现渲染**成一条系统消息 |
| **对话** | 用户说了什么、模型答了什么、调了什么工具 | `dialogue: Vec<Msg>` | 原样带上 |

- 请求由**唯一一处**装配（`engine::assemble`）：`[身份][本回合工具面][对话…][本回合提示]`。为什么这样分：

- 参数是**派生**的（登记处 + 提示词册 + 工作区路径）。把它渲染成"第 0 条消息"存进会话，就等于让参数冒充对话——回档要单独照顾那一条、压缩要给它留偏移、改一个参数（例如登记处里的工具形态）还得把整个会话从盘上重建。
- 分开之后：`rewind(0)` 就是**对话清空**；压缩只算对话的字符数；改形态只改参数里的一格，下一回合自然生效；**"回放与实时产出同样的消息"只约束对话本身**——对话是事实，参数是派生。

## 六、节点执行只有一条管道

- 一个节点的执行回合是**核心的能力**，不是前端的能力：核心把任务提示词作为**派发行**注入该 agent 的会话（`note_task` / `dispatch_task`：界面上是系统行，上下文里是 **user 角色**，见上"系统消息"），再由生成线程跑该会话；CLI 与 Web 只是各自"点火"（`drive_node` / `prepare_node`），**不各写一套派发**——同一件事两处实现必然一处对一处错（例如把核心的任务提示词当成用户发言，或把派发写成 system 角色、请求里一条 user 都没有而被供应商拒收）。

- 派发的生成**跟随设置里的流式开关**：节点在界面上同样逐字出（`llm_opts(true)`）。

## 七、回档：三种模式 + 工作级标记

- 回档是**版本控制专属**：只有工作台策略带 `versions` 能力位（`versioned`）的会话才有留档 / 删除 / 恢复；`plain` 会话没有版本库，三种模式一律拒绝（文案以 `src/units/business/lifecycle/service/rewind.rs` 为准），转录只往前加。
- 转录是**只追加**的内容日志（`Content`）：留档只追加一条 `rewind` 事实，不裁字节；只有删除与恢复会做物理裁尾（`cut_before` + 整份重写）。
- 回档的载体是**标记**（写进转录的 `rewind` 事件），不是"删掉就算"。用户在某一行的「回档到此处」上二选一：

| 模式 | 转录 | 行 id | 共享区 |
| --- | --- | --- | --- |
| **留档** | 追加 `rewind{mark,mode:archive,before,from,shared,heads,label}`；活动窗口 = `id<before` 或 `id>=from`，文件字节全留 | 新行从全量最大 id + 1 续号，被折叠的行 id **永不复用** | 主副本与每个受影响的沙箱一起物化到按行锚算出的提交点 `shared`；提交历史保留 |
| **删除** | 真的把文件重写到 `id<before`（不留标记） | 同上 | 主副本与每个受影响的沙箱一起物化到按行锚算出的提交点，并**丢弃**该点之后的提交；未提交内容先进 `lost/<agent>/@delete-<点>/`；删除点之后的留档一并作废 |

- **留档是全局检查点**：文件先于转录落位——`refs/archive/<mark>` 记下留档前的主线头（`target`）、每个受影响 agent **自己的工作线头**（`heads`，恢复时放回这条线，不是主线头）、各 agent 的存档线头（`saves`，沙箱快照）与 `since`（留档时刻的下一个提交号）；随后主副本与这些沙箱一起物化到目标提交点。沙箱里不一致的文件先备份进该 agent 的 `lost/<agent>/archive-<mark>/<路径>`（`work_lost` 列得出、`work_restore_lost` 按同名相对路径读回），再删掉、写上目标版本。文件写回失败会撤销档案引用；标记最后才写，避免"说已留档、文件还在新枝"。
- **恢复**（折叠分界上的按钮）：先读 `refs/archive/<mark>` 并校验目标提交还在、`since` 在；再把主副本与 `heads` 里每个沙箱一起物化回档案头（被覆盖的现状同样进 `lost/<agent>/restore-<mark>/`），把各 agent 的工作线放回 `heads` 记的头，然后**丢弃 `since` 及之后的全部提交**（留档之后长出来的分叉、以及更晚的留档引用一起作废），最后移除档案引用。转录在该标记记录处截断：标记与它之后的一切（含留档期间的新工作、以及更晚的标记）真的删掉。恢复过的档案不能再恢复一次。
- **屏障**：留档 / 删除 / 恢复前先把整棵子树里在跑的回合停稳——作废等待中的裁决队、取消生成，并轮询到核心交回会话（30 秒仍未收尾 = 拒绝，文件与转录都还没动）。三种模式都不跳过在跑会话，否则同一次回档只改半棵树。
- 标记里的 `label` 取折叠区间最后一条内容行（工具行 / 提示行 / 压缩提示不算，超长截 40 字），界面显示 `[留档] <label>`；没有内容行时退回"第 N 行"。

- **回档也是事件台的一等事实**：三种模式成功后，核心为每个受影响会话推一条瞬时 `rewound`（载荷 = 回档后的活动视图），并把该会话的**重置水印**推进到这条事件的序号。`history.open` 的 `live` 只取水印之后的事件；前端见 `rewound` 清空当前视图并按视图重建。这样刷新/多端不会再把回档前的旧批次当成实时尾巴，也解释了"重启后消失、刷新却还在"的差异（事件台是内存日志）。

- 跨会话同步：主会话回档时，**整棵子树**（子会话、孙会话……）按同一个**回合 id** 收窗——每个会话截到"最后一个 `turn ≤ T` 的行"，并写同一个 `mark` id（同一份 `shared` / `heads` / `label`）；恢复时按这个 id 在各会话里找到标记并一起截断、一起物化。
- **删除不可恢复，但会先报账**：删除点之后还存在的留档引用（`refs/archive/<mark>`）会在同一次删除里作废；后端先拒绝并报出数量与标记，界面据此二次确认，确认后才带 `force` 重放。作废只删引用，文件已经落到删除点，未提交内容在 `lost` 里。

- 实现位置：`src/units/business/lifecycle/service/rewind.rs`（`lifecycle` 单元，见 [docs/lifecycle/README.md](../lifecycle/README.md)）；本节的判据与顺序以那里为准。

- **按行精确物化共享区**：每个提交记录带 `(agent, line)` 锚（用户投喂锚在主会话当时的行号，agent 提交锚在它自己会话的行号）。回档时按"各会话的保留行"逐个提交比对，取最后一个"所有锚都还没越过保留行"的提交点再物化（**没有锚的提交不参与选点**：外部同步与用户投喂都带锚，无锚说明来历不明，算进"之前"会让留档永远停在外来提交上）；删除额外丢弃不再可达的提交并把各 agent 的基线对齐到该点，恢复同样丢弃留档之后的提交（回到留档操作前的线）。行锚由每席的 `MemberTools.line` 随转录推进（成员工具面由 `src/units/business/agentloop/domain/assembly.rs` 装配，`line` 随会话持有）：显式 `work_commit` / `work_push` 经 `ToolCtx` 拿到它，写工具落地后的自动快照与批次末的沙箱采纳都读同一处（采纳的提交记 `source=external`、作者仍是该 agent，所以留档同样能把它退掉）。

- 被折叠 / 被截断的行不进发送视图，也不进压缩摘要的输入；活动窗口由内容日志 `Content::folded_away()` 算（`src/units/business/transcript/domain/content.rs`），界面按 `rewind` 事件画折叠分界（见「上下文压缩」）。

## 八、上下文压缩

> **压缩改的是"发给模型什么"，不是"留下什么"。转录永远完整，旧内容用户照样能查看。**

### 谁压

- **agent 自己压**：核心把该会话的**被总结前缀**发给总结模型（默认就是该 agent 的模型），只给一个工具 `compact`，提示它写下 summary。系统**不替它总结**；保留段与之后的新内容不参与这次总结。

### 怎么落档

- 压缩记录是一条**转录行**：`kind = compacted`，正文 = 摘要，`payload.up_to` = 第一行保留行的 id；它不产生对话消息，只影响发送视图；发送视图变成 `[system] + [摘要] + 第 up_to 行起原样保留的内容 + 之后的新内容`；`up_to` 之前的内容**不再发给 agent**，但仍完整留在转录里。重启/回档按最后一条压缩记录行重建；它之前的行如果不再满足保留条件，就不进对话；界面显示压缩记录（"第 N 行之前已压成摘要，此后原样保留"）与摘要；它和普通行一样可以**删除 / 留档 / 恢复**：删除或留档它 = 解除这次压缩，恢复 = 重新压回；删除/留档保留段里的行按"删这一行及其后"的时间线语义处理：删到压缩记录行之前会连带解除压缩；想保留摘要又要折叠保留段，用**留档**而不是删除。

### 多次压缩 = 滚动摘要

- 第二次压缩的输入是"**上一份摘要 + 它之后、本次切分点之前的内容**"，输出**一份**新摘要。
- 发送视图里永远只有最后一条压缩记录行生效；更早的压缩记录行只作为历史行保留。

### 触发

| 方式 | 说明 |
| --- | --- |
| 自动 | 每个回合开始、**注入本轮输入之后**：`say` / `continue_reply` / `dispatch_task` / `discussion_turn`。看最近一次调用的 token（优先供应商回的 `usage` 的 total；拿不到按字符估算，**界面标注"估算"**）；超过 `模型窗口 × compact_at_percent` 就先压一次 |
| 手动 | 状态栏「工具」菜单的「压缩上下文」；输入框整段恰好是 `/compact` 时执行 |
| **不可自助** | agent **不能**在普通回合自己调 `compact`：压缩只由**系统阈值**或**用户**发起（行为可预测） |

- 本轮新注入的用户消息 / 派发任务**原样保留**，不会被压进摘要；更早的内容才进摘要。

### 设置

- `models.yaml`：每个模型可声明 `context`（窗口大小）；填 0 / 留空 = 用户不填，自动压缩按 128K 兜底；`settings.yaml`：
  - `compact_at_percent`（默认 70）：上下文用到窗口的百分之多少就自动压（0 = 关）；
  - `compact_keep_percent`（默认 15）：压缩时至少保留最近多少内容（占窗口 %；0 = 只留摘要）；
  - `compact_model`（默认空）：空 = 会话同模型；非空 = 登记处里的模型 id。
- 它是全局设置，只在压缩触发时解析（不按回合、不刷新会话）；窗口装不下被总结前缀时如实报错。

### 压不动就如实说

- agent 没给出摘要（没调工具 / 调用失败）→ 记一条通知（"压缩没成功：…"）并**继续用完整上下文**；没有可压缩内容（对话已在保留预算内 / 只剩上一份摘要）→ 手动给提示、自动静默跳过，不空转模型。

- **不静默降级、不假装压过。**

### 通用性

- 压缩是**所有会话通用**的能力，**单 agent 会话同样适用**；代理会话也是 `Session::Single`（一条持续对话，窗口取核心默认模型），压缩与状态栏用量同一套。协作主会话没有一条持续发给模型的对话，不显示上下文用量。

### 过期读取的占位符

> **读过的内容被改了，就别再拿旧内容当事实。** 与压缩同属"改发送视图、不动转录"。

- **读事实随工具行落盘**：成功的非截断 `read` 在工具行的观察事实里记"覆盖区间 + 读来源"（工作树 / 路径 / 当时的整份指纹 / 行数）；发送视图用的读事实由它派生，不再单独落一份。整份读派生一条 `1..=total_lines`，`offset` / `limit` 截过的分段读**每段派生一条**——大文件只能分段读，但读过的那几段照样会被占位符照看。空文件、越界段、`lossy` 与单行截断都不产生读事实（派生规则见 `src/units/business/tools/api.rs` 的 `ObservationFact::read_facts`，用例 `src/tests/tools/gate.rs`）。
- **开关与保底都是落盘事实**：`meta.context_freshness`（默认关）与 `meta.freshness_keep_percent`（默认 80，范围 0–90；0 = 不保底，100 等于永不替换所以不允许）。关 = 只记事实、发送视图原样；开 = 发送前判一次过期。两个值都写在**工作根** meta 上、子会话沿根继承；落盘是为了回放与实时产出同一条请求。
- **判定按内容，结论分三态**：指纹相同 = `SameVersion`；路径已不在对照物里 = `Changed`；否则取新旧两份正文，把"读过的那几行"当成连续行窗口在新内容里找——找到 = `Shifted`（版本变了但那段内容还在，头部插行导致的移位也算），找不到 = `Changed`（`Workspace::judge_reads`）。
- **两个消费者对 `Shifted` 刻意取不同答案**：占位符只换 `Changed`——模型看到的旧内容仍然可信，只是行号可能移位，没必要付一次缓存失效；写门禁只认 `SameVersion`——整份覆盖授权不能抹掉没看见的改动（版本变了就必须重读）。同一份读在两个地方可能得到不同结论，这是设计而不是不一致（两个策略分别落在 `src/units/business/agentloop/engine/driver.rs` 的 `freshness_now` 与 `src/units/business/versions/service/driver.rs` 的 `SessionWriteGate`）。
- **过期只换那一条工具结果**：整条换成 `[已过期：<path> 第a-b、c-d行，读取后文件已修改；需要时重新 read]`；同一条工具结果里的多段读按消息归并成一个占位符（相邻/重叠区间合并，隔开的用顿号分开）。按**正文**定位消息（压缩会移走旧消息、下标会漂），正文找不到就跳过。
- **保底 = 只替换前缀之后**：先按字符数（≈4 字符 / token）估出发送视图总量，前 `freshness_keep_percent`% 的消息原样保留、只替换其后的过期读——KV 缓存是位置绑定的前缀缓存，保住前缀才保得住命中。这个估算只用来切前缀，不参与用量与计费口径。
- **省得不够就不换**：一次替换省下的正文不到 8000 字符（≈2K tokens）时整次回退、原样发送——换一次要付一次缓存失效，不值。判定失败、没有工作区、开关关、省得不够，都原样发送——不静默丢内容。
- **两边都判，对照物各是各的**：读事实里的 `worktree` 为空 = 读的是主副本，对照主线树（`judge_reads` 的主副本分支）；非空 = 读的是那个 agent 的私有沙箱，对照沙箱当前内容（`ReadQuery.sandbox`）。所以别的 agent 推送主线只让主副本的读过期，不影响谁的沙箱读。
- **shell / 模块工具改的也算**：它们写的是自己的沙箱、批次末只进存档线（见「共享区」），所以沙箱里的读会被它们改过期；主副本要等 `work_push` / `work_sync` 才变。
- **代价**：替换点之后的 KV 缓存全部失效，所以它是用户选的成本项、不是默认行为；保底与「省得不够不换」都是为了让这一次替换值回这次缓存写。
- **入口**：会话配置的「上下文」区与创建向导的同两项都走 `set_context_freshness`，参数 `{session_id, on, keep_percent}`（省略 `keep_percent` = 沿用现值；超过 90 直接拒绝）；作用在工作根、生成中拒绝切换，在建会话时给定则随创建一起落 meta。`SessionView.freshness_keep_percent` / `freshness_stats`（最近一次替换的 `judged` / `replaced` / `saved_tokens` / `skipped`）是同一份事实的快照，面板的「过期占位符」行读它。

## 九、思考强度（会话级）

- **一个工作一个值**：写在 SessionMeta.thinking（工作根持有）；子会话沿 `meta.parent` 共享同一个档位，不各存一份。
- **作用范围**：只作用于**对话生成**——单 agent 的发言、代理会话的核心对话、协作成员的回合。
- 核心内部编排（拟名单 / 裁决 / 验收 / 摘要）保持供应商默认：它们不是"这一场对话"，不该跟着用户拉高成本。
- **解析**：会话档（`SessionMeta.thinking`）优先，其次模型的 `thinking.default`；都没有 = 不发思考参数。
- 模型没登记会话选的档 = **切换时拒绝并列出模型**，生成时同样如实报错（不静默降级）。
- **入口**：状态栏的「思考」chip 与配置页的同一选择器都走 `set_thinking`；生成中拒绝切换。
- 写在工作根 meta 上，切换后整棵子树的会话从内存丢掉、下一次访问按新档重建。
- **界面只列可用档**：状态栏与配置页只列这组模型都登记了的档；没选过档时直接选中这组模型的共同默认档。
- 各模型默认不同（或都没设默认）时显示「各模型默认 / 未设置」，并保留一个「跟随默认」状态项。
- **改登记处**：映射从 `models.yaml` 现解析；下一次生成就用新映射。删掉一个仍被旧会话选中的档，那条会话的下一次生成会报"模型未登记该档"，由用户换档——不自动替代。

## 十、边界语义

- 边界处置按情形约定：并发按 agent 串行、删主会话级联、停止代理会话按编排归属一起停。

| 情形 | 语义 |
| --- | --- |
| 同一个 agent 的多个节点 | **串行**（一个会话一次只能跑一轮）：派发时按"该 agent 已有在跑的节点 / 本轮已派过"跳过，下一轮推进再派（`spawn_ready_nodes` 的 `busy`/`taken`） |
| 不同 agent 的节点 | 照旧可并发 |
| 删主会话 | 级联：按 `meta.parent` 收集整棵子树，移出内存 → 收集待删目录；guest 销毁与目录删除在调用方线程按序执行（先停 guest，再删目录），删完目录后在**后台线程**按租约撤围栏授权（先删目录让产品根内授权自动走「路径不在 → 只销账」快分支，外部根的递归撤权不占用户等待路径）；子树里任一节点在生成中则**整体拒绝**（不删到一半） |
| 删 agent 会话 | **不允许用户单独删**：`HistoryOps::delete`（经 `Lifecycle::history_delete`）如实拒绝，理由"由核心管理，删父会话会一起删掉"；内部的 `session::History::delete` 仍是纯存储机制 |
| 停止主会话 | 不启新节点；已在跑的 agent 会话各自停 |
| 停止**代理会话** | **相关会话一起停**（按编排归属级联）：用户点的那一下就是"全停" |
| 用户进 agent 会话发言 | 正常单 agent 一轮；它下一次发言会带上这段（讨论里能影响它），此后仍要用讨论动词表态 |
| 用户主动中止 | 计数**不再工作**（不注入提醒）；用户可能正想和它讨论 |
| 生成中的控制按钮 | 「继续」在核心调用 / 模型输出阶段**变成「中止」**——用户要能随时停，而不是只能等 |
