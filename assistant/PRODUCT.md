# 产品与用户旅程

> 本文档回答：用户怎么用这个产品。
> 产品 = 装配者 + 模块。产品入口只负责：启动、发现、装配、交互面选择、退出。
> 一切功能行为由模块自治（见 MODULE_DEV_GUIDE.md）；产品入口不认识任何业务。

## 分层铁律（本文档的灵魂）

| 决定 | 归属 |
|---|---|
| 启动什么、扫描哪里、排除谁、额外拉起哪个外部模块、退出语义 | **产品入口（装配者）** |
| 某配置缺失时怎么办（例：无密钥时拒绝聊天还是降级） | **用到它的模块自决** |
| 交互面里能做什么（组件、命令、提示文案） | 模块经 `ui.contribution` 声明，UI 模块渲染 |
| 谁连着谁 | 核心配对（事实，非决策） |

推论：密钥只是某个模块的内部概念。产品入口从头到尾不知道"密钥"存在——
用户在调色板看到 `set-key`，是因为 secrets 模块声明了这个命令，不是因为产品了解它。

## 产品形态

一个命令，装好的模块即产品。

- **产品进程** = 装配者 + 核心 + 编译内模块（Dart 硬约束：进程内组合必须编译期引用）+ 终端交互（REPL）
- **交互面是模块**：终端 UI（ui_cli，编译内）恒为兜底；GUI 是外部模块进程，装了才可选
- 交互面可并行存在多个，核心对"几个交互面"无感知——它们只是普通模块

## 第一分钟（用户旅程）

```text
$ solomni                                  <- 命令名为占位，正式名待定
[发现] conversation, llm_gateway, secrets, ui_cli    <- 扫描 modules/，纯事实
（终端进入对话模式；help 查看全部组件与命令）

> send 你好
[conversation] 未配置密钥，无法聊天        <- 拒绝与否、怎么提示，由聊天链路自决
> set-key llm sk-****
[secrets] 密钥已保存
> send 你好
你好！今天想聊点什么？
> exit
$
```

- 启动只报告**事实**：发现了哪些模块。不解释任何模块的用法——那是模块自己的事
- `help` 走 `ui.render`（模块能力，调色板）；`exit` 是产品生命周期，归装配者
- `send` / `set-key` 来自模块声明的命令，产品不硬编码它们

## 启动选项

| 形式 | 行为 |
|---|---|
| `solomni` | 默认：装配 + 终端 REPL |
| `solomni -gui` | **额外**拉起一个 GUI 模块进程作为并行交互面（终端 REPL 仍在） |
| `solomni -gui <模块id>` | 指定拉起哪个 GUI 模块（模块 id = modules/ 下文件夹名） |
| `--without=<模块id>` | 本次不装配该模块（既有装卸语义） |
| `--verbose` | 详细诊断（默认状态行从简，不与聊天流抢屏） |
| `--port=` | 开发者覆盖；默认端口自动分配，用户与 GUI 模块进程不感知 |

`-gui` 的装配规则（装配层也无静默选择）：

- 未安装任何 GUI 模块 → 启动即报错，说明装法
- 恰好一个候选 → 直接拉起
- 多个候选且未指定 → 列出候选并退出，**不替用户选**
- 点名的模块存在但不支持当前平台（无对应 `dev`/`dev.bat`）→ 报"不支持当前平台"

`-gui` 拉起走模块自备的 `dev`/`dev.bat` 契约脚本（怎么跑、依赖与环境都是模块自己的事；
平台支持声明 = 脚本存在性）。产品启动器 `bin/solomni`(.bat) 只是便捷薄壳：免去
cd 与长路径，不含任何业务。

## 退出语义

| 事件 | 语义 |
|---|---|
| GUI 窗口关闭 | **模块离线**：核心重配对，产品继续运行；终端 REPL 一直是兜底交互面 |
| 终端退出（`exit` / Ctrl+C） | **产品进程消亡**：编译内模块随之消亡，外部模块进程被终止 |

原则：模块进程的消亡是离线事件，产品进程的消亡才是产品退出。
终端不是特权交互面——它只是宿主进程的物理同居者。
若未来把终端 UI 也外置为模块进程，产品即可无头常驻，任何交互面关闭都只是离线（后置项）。

## 模块装卸的用户感知（v1）

- 放入/移出 `modules/` 文件夹 + 重启生效；启动时的 `[发现]` 清单即全部反馈
- 运行中的模块进程死掉 = 即时离线、消费方即时降级（已由核心配对保证）
- 无"不可卸载"清单：卸载 ui_cli 的后果与其他模块一样，是降级而非崩溃

## 后置工作（不在 v1）

- 命令名定稿与二进制打包（当前开发态：`dart run` 于 `apps/desktop_demo`）
- GUI 模块的预编译产物（免每次 `flutter run` 的编译等待）
- REPL 运行时切换 GUI（`/gui`，装配者运行期拉起）
- 无头常驻模式（终端 UI 外置化）
- 热装卸（免重启发现新模块文件夹）
