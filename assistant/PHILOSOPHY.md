# 项目核心理念

> 本文件只记录抽象概念与终极目标，不涉及任何具体实现。
> 实现可以变，理念不变。

## 终极目标

构建一个去中心化为常态的跨平台 AI 助手：

- 模块自治，可独立运行、独立替换
- 中心化只是能力，不是前提
- 无上帝：没有任何模块（包括核心）有资格决定什么该被共享

## 核心理念

### 1. 模块自治（Module Autonomy）

每个模块是一个自治程序：拥有独立入口、独立状态、独立生命周期。
它对世界的全部认知是一份声明——我提供什么、我需要什么。
上线、下线、重连是常态事实，不是异常事件。
没有核心时，模块以自己的方式满足自己的需求。

### 2. 中心化是能力，不是前提（Optional Centralization）

去中心化是默认状态；依赖中心化协调是一种可选能力。
类比：同一块网卡，有基站走基站，没基站自组网。
没有核心，模块各自实现需求；有核心，值得共享的才被共享。

### 3. 无上帝（机制与策略分离）

核心只有三个动词，全部是服务，没有一个是权力：

- **校验**：拒收非法事实（身份冲突、拓扑成环、接线指向未知）
- **配对**：登记"谁需要什么"与"谁提供什么"的完整对应，永不挑选
- **投递**：按封套机械转发

决策权永远在边缘：消费方声明首选、部署者显式接线、调用方定向调用。
校验由核心承担，不是因为核心地位更高，而是因为"全局唯一""拓扑无环"
这类保证任何单个模块都无法自证——模块依赖这些保证，核心作为公共品
提供它们（依赖倒置：模块依赖抽象的保证，核心提供实现）。

判据：**决策是在多个合法选项间挑选；校验是拒绝非法事实。**
核心可以拒收一张假身份证，但不可以替你挑选餐厅。

### 4. 涌现式中心化（Emergent Centralization）

共享 = 提供方主权声明 + 消费方策略选择，双边同意才成立。
中心化是涌现的结果，不是设计的前提。

一个能力同时有多个提供方在线，不是错误状态，而是**消费方的选择空间**。
选择权落在消费方，落地层次：声明时声明首选（Need.provider）、
装配时显式接线、调用时收到候选清单后定向调用。
核心如实呈现候选，绝不代为选择；"曾经唯一"只是巧合，
不构成在任提供方的特权。

### 5. 事实驱动配对（Fact-driven Pairing）

配对永远是当前声明的纯函数：

- 声明到达或离开，配对即重算；同 id 重连 = 一次离开加一次到达
- 开放世界没有"最后一个提供方"：一切选择基于当前快照，无需等待未来
- 提供方离线 -> 消费方自动降级；提供方回归 -> 配对自动恢复
- 配对变化推送到受影响的消费方：事实应随事实的变化到达；
  轮询是用重复劳动换取本可直接送达的事实，是一种浪费

### 6. 辅助性原则（Subsidiarity）

事务在能胜任的最低层解决；中心只做局部做不了的事。

### 7. 状态所有权排他（Exclusive State Ownership）

数据归属模块，无共享数据库——这是模块间"无冲突"的根源。
跨模块流动的是消息，不是状态。

## 不变量（Invariants）

无论实现如何变化，以下规则不可违反：

1. **协作单路径**：模块间协作只经核心，无点对点直连
2. **消息边界**：边界上只有消息，永不共享对象引用
3. **薄内建**：模块的内建实现有意保持最小，富实现只放共享侧一处
4. **配对即事实**：接线永远是当前声明的纯函数；成员变化即重算，
   并推送给受影响的消费方，禁止轮询
5. **无静默选择**：核心只在合法事实间配对、只在非法事实上拒收
   （重复 id、成环、接线指向未知，是仅有的拒收场景，装配期/接入期
   fail-fast）；多提供方是消费方的选择空间而非错误，缺提供方是降级
   而非失败
6. **可替换**：换任意模块、换任意核心，互不牵连
7. **降级而非崩溃**：能力缺失导致功能降级，而不是程序失败
